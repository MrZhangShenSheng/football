1. 背景与审计结论

起问：预测模型的多个影响因子是否主要作用于 90 分钟胜平负？比分（CRS）、半全场（HAFU）、总进球（TTG）是否吃到因子？逐脚本审计（dc_predict.py / boldplay.py / score_ev.py / SKILL.md Step3.5–6）得到覆盖矩阵：

三大缺口：

  1. 因子不传导——战意状态机判"平局×1.30"时比分矩阵纹丝不动，玩法间内部打架（三向推平局、比分 top1 却是 1-0 主胜）。
  2. 三池裸 DC——v5.1 boldplay 的 CRS/TTG/HAFU 池 EV 用 100% 裸 DC 概率打体彩（抽水 20%~34%），胜平负却有 Pinnacle 融合校准；未校准尾部误差直进 EV（"0球正值项 ρ 同向嫌疑"的根源）。
  3. HAFU 结构最弱——λ×0.45 硬分割 + 上下半场独立假设，无市场校准、无因子注入，连池赔率都需另走 sporttery_matches 特殊抓取。

3. 总体架构

图1 · 现状断链 vs 目标回传链。因子判断仍是 skill 流程的知识工作（Agent 算修正三向），代码只提供"三向 → 全玩法重标定"的概率原子——战意状态机不写进 Python。

数据流单向：fd 历史拟参数 → cache（half_share / temperature）→ dc_predict 出概率 → skill 修正三向 → --adjust 回传重标定 → boldplay EV。无循环依赖。

4. 步骤 1：三域重标定（因子传导）

核心简化：主胜格（i>j）、平局格（i=j）、客胜格（i<j）三域互斥，不需要迭代 IPF——每域乘一个常数即精确对齐：

w_H = target_H / p_dc_H        P'(x,y) = P(x,y) × w(所属域)
w_D = target_D / p_dc_D        三域权重对齐后矩阵和自动 =1（target 归一）
w_A = target_A / p_dc_A

性质（IPF structure conservation 的特例）：域内相对结构不变（1-0 与 2-0 比例保持 → ρ 低分形状、TTG 形状保留），仅三向质量重新分配。战意抬平 → 0-0/1-1/2-2 等比放大 → TTG 低档自然微升。

HAFU 传导用条件分解：9 键 = HT×FT（第二字母为 FT），保持 P(HT|FT) 不变，按 FT 三列（*h/*d/*a）乘域权重对齐修正后三向，HT 边际随条件分布自然传导。

接口（dc_predict.py）：

reweight_matrix(p, target) -> np.ndarray
reweight_hafu(hafu9, target) -> dict
CLI: --adjust 0.42,0.31,0.27 -> JSON 增加 "adjusted" 块（三向/比分/TTG/HAFU 重标定版）
boldplay.mix_candidates 增加可选 adjust_map（场次编号 -> 三向），有则 EV 全从重标定链算

护栏：① target 三向和 =1（±0.001）否则报错——防 skill 流程手算失误静默进矩阵；② target 任一项 <0.01 时 clamp 并 warn——防修正系数叠乘压塌某域；③ target 必须是"融合+因子修正后"的最终三向（裸 DC 修正禁止直传，JSON 加 source 字段标注——学术依据见 §11 ⑤：7220 场验证裸结构模型无市场增量）；④ before/after 同 JSON 输出，报告可审计。

5. 步骤 2：池级温度校准

定义：p_T(k) ∝ p(k)^(1/T)，每池一个标量；T>1 平滑（修 DC 过度自信尾部）、T<1 锐化。作用概率空间 = Guo et al. 2017 作用 log 空间的标准变体（最小化 NLL 时一致）。为什么用温度不用体彩自举融合：体彩赔率是含水价格，自举校准循环论证；fd 历史+自家语料独立干净。

作用顺序铁定：先重标定、后温度（矩阵三向传导 → 池聚合 → 温度化），防止顺序颠倒破坏三向对齐。

拟合协议（walk-forward 无前视）：fd 8 联赛×4 季按日期排序，前缀 ≥50 场起步拟 T，其后各场用"该场之前数据"的 T 算 log loss，滚动前移（与 backtest.py 同构）。逐池观测目标：TTG=命中档、CRS=命中比分（矩阵外并入"其他"档，映射按 dump-odds 存档口径）、HAFU=命中 9 键。HAFU 温度暂不启用：143 场语料 half 覆盖仅 9.7%（9/93），fd 历史 HTHG/HTAG 虽全覆盖但线上 HAFU 池无法历史回溯（sporttery_matches 无日存档）——上线后前瞻监控攒样本。

消融线：bootstrap CI 下界 >0（log loss 改善确证为正）才启用该池 T；否则落盘 T=1（代码保留、参数回落 = 删除效果）。

消费端：boldplay 三池 EV、dc_predict --adjust 输出链全部用温度后概率；报告展示 T 前后对照，EV 排序变化可审计。产出 engine/cache/temperature.json：每池 {T, n, ll_before, ll_after, bootstrap CI, fittedAt}。

6. 步骤 3：HAFU 半场参数升级

数据：fd CSV HTHG/HTAG 列（fetch_rows 全列直读，现成），8 联赛×4 季每联赛 1200+ 场半场计数。

  • 参数 1：联赛级半场占比 s = ΣHTHG+ΣHTAG / ΣFTHG+ΣFTAG，β 收缩到全局（先验 ~200 球），clamp [0.3, 0.6]（λ 守恒防呆）。替代硬编码 0.45。队级不做——一季 34 场×场均 1.3 半场球，β 收缩后必退回联赛级（YAGNI）。
  • 参数 2：半场 ρ_half——复用 dc_tau 作用于半场比分矩阵（半场 λ≈0.6 低分密度高，ρ 效应比全场强）。只修半场段、不修下半场段：竞彩 HAFU 判 HT/FT 符号，半场段有直接观测；"下半场比分"是构造量无观测口径，其低分偏差由 FT 三向重标定兜底。
lh1 = lh × s_league, la1 = la × s_league     # 联赛级占比
半场矩阵 = 泊松(lh1, la1) × dc_tau(ρ_half)    # 低分修正
下半场 λ = 全场 λ − 半场 λ                     # 总 λ 守恒

回退：日韩瑞沙（league 库无半场列）→ 全局 s + 全局 ρ_half；half_share.json 缺文件 → 0.45 / ρ=0（现状行为）。产出 engine/cache/half_share.json：{league: {s, rho_half, n}, global: {...}}，生成脚本 half_params.py（独立可重跑）。

验证：fd 历史 walk-forward 上 HT/FT 边际校准 + 9 键 logloss，before/after 对照。

7. 验证协议（fd 历史 walk-forward）

验证语料从"143 场回填语料"升级为"fd 多季历史"：fd CSV 自带 FTHG/FTAG（CRS/TTG 观测）+ HTHG/HTAG（HAFU 观测全覆盖，绕开 9.7% half 覆盖死结）+ PPCH/D/PPCA Pinnacle 收盘（融合三向可复现 → 重标定链可复现）。8 联赛×4 季数千场，统计功效充足。历史"当时 DC 参数"不可复现的问题（fd 联赛无版本存档）由 walk-forward 滚动拟参解决。143 场语料降级为上线后前瞻监控集（线上实测 vs 离线验证对照）。

消融矩阵：2³ = 8 组合全跑（基线 / +重标定 / +温度 / +HAFU升级 / … / 全叠加），报告主看逐池单步增量与全叠加 vs 基线。

步骤性质验收

12. 风险与回退

  • 每步独立回落：零破坏设计（见 §7），出问题回落参数即恢复现状行为。
  • 温度补偿错位：temperature.py 必须在最终概率链上拟（顺序 §5 铁定），否则 T 补偿旧 HAFU 偏差后升级错位。
  • 重标定压塌：clamp+warn 护栏（§4 ②）；临场复扫 adjust_map 不同步重算 = 旧三向新赔率错配（SKILL.md 流程明示）。
  • 消融不过：按验收线回落参数、保留代码——与项目"无正增益即删"纪律一致。
