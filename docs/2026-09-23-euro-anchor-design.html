欧指市场锚补全设计

日期：2026-09-23 状态：已拍板（方案C：骨架B+节奏A，大哥确认） 开发者：sszhang

一、背景与问题

目标：提升单场比赛预测准确率（胜平负方向 / 概率校准 / 比分衍生三口径）以提升方案命中率。

错题归因账本（59 条，截至 09-22）事实：

  • F9 占 50/59（85%）：出票时模型本就无把握（p_final 0.26~0.60）——选腿问题，非模型问题；
  • 大量错题 pinSource=none：日职/韩职/北欧/沙特/南美等 fd 不覆盖联赛（约 165/734 ≈ 22% 场次）没有市场锚，纯 DC/模板裸奔——结构性准确率断层；
  • 错题赛果平局占比极高（平局专项为路径3，本设计不碰）。

四条候选路径（补锚 / 联赛校准扩容 / 平局专项 / 临场层）经拍板优先级 1>2>3>4，本设计只做路径1：给无锚场次补第二市场源（okooo 99家平均欧指）。

关键利好：对齐零成本——okooo 页面直接用体彩编号与中文队名，join key = 日期 + 体彩编号，不依赖 _aliases.json。风险：99家平均欧指 ≠ Pinnacle，平均价含高抽水小公司，去水后有系统偏差（长赔端为重灾区），必须对拍验证后才能接入。

三、方案C设计：骨架B+节奏A（两步交付）

第一步 · 采集存档层（立即落地，只采不判）

  • 新增 engine/scripts/euro_fetch.py：日期页为主入口、期次页为辅（复用 sfc_fetch 解析），带重试，UA 复用 sfc_fetch 生产验证过的简单 UA；
  • 每场提取五元组：体彩编号、主客队、联赛、matchId、平均欧指[主,平,客] + 采集时间戳；
  • 存档 engine/cache/euro_odds/{date}.json（对标 score_odds 日存档，纯 JSON 不进画像目录），同日重跑幂等覆盖；
  • 接入点：run.py update 体彩采集步骤后追加调用，预测命令自动带上；
  • fd 覆盖与无锚场次一视同仁全采——前者是明天对拍样本，后者是后天接入受益人。

第二步 · 对拍验证与融合链接入（数据说话后）

对拍报告（euro_verify.py，样本 = fd 覆盖联赛双源同场）：

  • 指标三层：①方向 argmax 一致率 ②去水概率 MAE ③赔率带分层偏差（≤1.5 热门 / 中间 / ≥3.0 冷门）；
  • 门槛（初值可调）：argmax 一致率 ≥85% 且 MAE < 0.03 → 直接接入；不达标 → logit 空间仿射校正（系数用 fd 样本拟合，联赛间交叉验证确认跨联赛稳定后外推）再测；仍不行 → 降权或不用；
  • 样本 ≥50 场出首报，此后每周自动刷新。

融合链接入（改动集中在 dc_predict 锚装载逻辑）：

  • fallback 链：fd Pinnacle 有锚 → 现状不变；pinSource=none → 当日 euro_odds 存档去水+校正作 p_market；无锚无欧指 → 维持纯 DC；
  • 融合一律 import fuse()（双实现陷阱铁律）；
  • 诚实降级：pinSource="okooo"，报告可见每场锚来源；
  • 顺带收益：fd 断粮（503）时 fd 联赛也有 euro 锚顶上（freq 镜像之外第二道断粮保险）；
  • 保留门槛：接入后 walk-forward 无锚场次 纯DC vs DC+euro锚，RPS/方向改善 ≥1% 护栏，不达即回滚。

四、错误处理与测试

  • 405/限流：重试1次（间隔2s）→ 降级跳过，预测流程绝不因欧指采集失败阻塞，报告标 euroSource: null；

  • 防污染：独立目录，不写 00/01 画像、不碰 fusion.json、不影响出票冻结链；
  • 测试：pytest 基线 217 passed，新增4组单测（日期页/期次页解析 fixture、去水+校正、fallback三分支、存档幂等）；落盘新 JSON 后全量重跑。
