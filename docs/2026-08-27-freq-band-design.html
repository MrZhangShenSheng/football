一、背景：从一句质疑到漂移诊断

起因是大哥的质疑："比分总是取的最小赔率的比分，赔率只能代表购买的人多人少，并不能真实反映实际结果。"逐份重读设计文档后确认：系统在 08-24 之后逐步偏离了 bold play 的原始设计初衷。

节点原始设计当前实现漂移性质
概率源模型审计已证 DC 无增量（Route D：DC top1 命中 9.5% < 经验频率 11.5%，概率系统性高估 75%）A-MIX 用 DC 概率 × 体彩赔率算 EV，假装找到"正 EV"与自家审计结论矛盾
比分选择经验频率 × 赔率的正 EV 列表（真实赛果数据驱动）DC 模型矩阵 × 体彩赔率（Poisson 假设驱动）数据驱动 → 模型驱动
Pool Coverage（08-26）三池裸 DC 是待修问题温度/reweight 把无增量的信号修得更"精确"在错误基础上精修
EV 的意义接受负 EV，优化密度（Dubins-Savage bold play，万倍通道）追求"正 EV"选项，如同 value betting从 bold play → 伪 value betting

核心矛盾一句话：模型审计说"DC 打不过市场"，A-MIX 却在用 DC 概率找市场的"定价错误"——逻辑自相矛盾。大哥的质疑更进一步：体彩赔率本身反映投注热度而非真实概率，以它为基准的"正 EV"大概率是模型幻觉。

决策：比分选择回归数据驱动——分布形状来自真实赛果频率，赔率只做门槛、不做排序依据，DC 彻底退出比分选择链路。

二、设计原则（三条铁律）

  • 数据说话，模型不说话：比分分布的形状来自联赛真实赛果频率；球队信息只平移位置，不用 Poisson 造分布（Poisson 系统性低估方差已被自家审计证实）。
  • 赔率只做门槛，不做排序：赔率回答"杠杆够不够"（形状带），从不回答"选谁"（选谁只看真实频率 q）。购买热度不参与决策排序。
  • 宁可空轮，不硬凑：无合规比分则跳过该场；不足 4 场则关档不出票。4 串 1 一个凑数腿能废掉整票（继承 08-24 原设计的"关档保护"）。

三、核心方法：联赛模板 + 球队平移（分层经验贝叶斯）

3.1 平移量计算（乘法进球模型）

联赛基准与两队近期状态（近 10 场，取 data/01-teams/ 球队画像 / 体彩 insight 近 10 场）：

联赛基准: 主场场均 1.45 球，客场场均 1.10 球
主队近10场: 场均进 2.1 / 失 0.8    客队近10场: 场均进 0.9 / 失 1.5

λ_h = 主队场均进 × 客队场均失 / 联赛主场场均 = 2.1 × 1.5 / 1.45 = 2.17
λ_a = 客队场均进 × 主队场均失 / 联赛客场场均 = 0.9 × 0.8 / 1.10 = 0.65

本场目标位置：总进球 T = 2.82，净胜球 D = +1.52——频率表整体向"主队中等净胜"方向平移。

3.2 平移映射（保形状、调位置）

拿到 (λ_h, λ_a) 后不用 Poisson 造分布，对联赛频率表做二维重加权：

# 每个比分 (h,a) 的坐标: t = h+a（总进球轴）, d = h−a（净胜球轴）
# 联赛基准位置 (T̄, D̄)，本场目标，带宽 = 联赛 t/d 标准差
# 高斯核重加权：靠近本场目标的比分按距离比例抬升，靠近基准的相应回落

q_new(h,a) ∝ q_league(h,a) × K(t−T)/K(t−T̄) × K(d−D)/K(d−D̄)   →   归一化
  • 小样本护栏：新赛季前几轮球队画像不足（近 10 场不满）→ 平移退化为纯联赛频率（λ 直接取联赛均值），零破坏降级。
  • 回测定生死：核重加权若回测无正增益，降级为不平移；带宽不手调，由回测选定。

四、选比分三步法

示例（单场判定）

比分q（平移后）赔率判定
1:110.2%6.5❌ 赔率太低（杠杆不够）
2:04.5%12.5✅ 桂林带 → q 最高者胜出
0:22.0%22.0✅ 梅州带（合格但 q 不及 2:0）
4:00.3%40.0❌ 出现太少（q < 1%）
形状带边界待核对：10~17 / 18~28 是当初按大奖形状反推的值。搜索配额恢复（08-31）后，用体彩 CRS 历史实际开出的大奖比分赔率段分布核对一次；核对前沿用现值。

五、兜底与关档

  • Tier 3 兜底（从 1:1 / 1:0 / 2:1 里挑最高赔）——砍掉。它的本质是"没辙了拿赔率凑"，恰是本次要治的病。
  • 某场所有比分不合格（q 都低或赔率都不在带内）→ 跳过该场选别场。
  • 合格场次不足 4 → 关档不出票，不硬凑（4 串 1 一个凑数腿能废掉整票）。
  • 连续 26 轮翻身档未中 → 强制复盘条款继承原设计，不变。

六、A-MIX 退场方案（开关切换 + 回测定生死）

boldplay.py 增加 --method 开关:
  --method=freq    ← 新方法（联赛频率+球队平移+形状带+q 排序），默认
  --method=amix    ← 旧方法（DC×体彩 EV 全量扫描），保留一个月过渡
步骤动作产物
1 · 上线新方法默认出票（首期仅 CRS 池）freq 链路生效
2 · 回测在已回填赛果（data/02-results/ corpus）上 walk-forward：两法各自会选什么比分、各中几个、所选比分平均赔率（杠杆对比）回测对照表
3 · 定夺（一个月后）回测占优 + 实盘正常 → 删除 A-MIX 及其服务件；表现异常 → 一键切回 amix + 复盘退场归档报告

七、DC 边界与 TTG / HAFU

链路处置
比分（CRS）选择DC 彻底退役；温度 / reweight / half-ρ（08-26 pool-coverage 产物，均为 A-MIX 服务件）随 amix 旧路径保留一个月，删除 A-MIX 时一并清理
胜平负 fusion不动——p_final = σ(0.4·logit(p_DC) + 1.0·logit(p_pin)) 是另一条链路，模型审计对它的结论是"71% 赔率权重是特性不是缺陷"
dc_predict.py保留（fusion 链路使用 + 叙事参考）；top_scores 仅作概率锚展示，禁止作为选项依据（SKILL.md 既有条款，重申）
TTG / HAFU首期不动（随 amix 旧路径保留）；二期按同样思路改造（各自的经验频率 + 各自的带）

九、验收标准

#验收项标准
1可复现性同一输入必得同一 q；无球队数据时平移自动退化为纯联赛频率（零破坏）
