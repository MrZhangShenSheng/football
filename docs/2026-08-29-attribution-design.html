预测偏差归因引擎设计（prediction attribution）

2026-08-29 · 作者 sszhang · 状态：设计已确认（含 10 条 review 修正全采纳），待分阶段实施 · 前置：corpus 语料（data/04-summaries/corpus.json）+ 实票账本（docs/2026-08-25-tickets-design.html）+ 体彩赔率日存档（engine/cache/score_odds/）

1. 问题

回测复盘长期停在表现层：corpus 记录"预测了什么（pick/odds/修正链）+ 结果（result）+ 中没中（dirHit/scoreHit）"，trend.html 统计命中率/校准，但"为什么错"始终是自由文本——复盘报告里的教训（如本轮"买热≠方向确认"）写完即弃，没有结构化沉淀。结果是同样的偏差反复出现却无法量化、无法排序、无法系统性反哺预测链的参数与系数。

项目的硬约束在先：修正系数须消融回测、无正增益即删（战意状态机=前车之鉴，连续负增益 56% vs 70% 待降级）。归因若直接改系数，就是用事后诸葛亮替代消融验证。本设计要把"偏差原因"从叙事变成可量化、可积累、经消融门反哺的结构化账本。

2. 目标与边界

维度定义
核心目标对每道错题结构化归因（1 主因 + ≤2 次因），滚动统计因子频次与损失量，攒够样本经消融门反哺预测链
不做什么不做实时归因（只回填后跑）；不替人定罪（消融门 + 人工拍板才动系数）；不追求 100% 覆盖（证据弱场留待确认）
反馈闭环归因产假设 → 消融定罪 → 人工拍板 → 改 fusion/缓存/preference；消融无增益则记账关闭

3. 因子分类法（四层 12 因子）

从预测链真实存在、可操作的环节反推，分四层——前三层修模型/补数据/记账随机，第四层是本轮实票教训催生的执行层（修纪律不修模型）。

层因子含义反哺对象
① 模型层
系统性偏差
可修参数/系数		F1 λ失准攻防强度估计错（预期进球 vs 实际进球偏差大）ξ / 重拟合口径
F2 ρ/平局参数DC 平局相关性强，0-0/1-1 常系统性低估ρ 参数
F3 市场锚分歧我们 p_final 与 Pinnacle 收盘分歧在先、我们错在后消融候选 → 降 a
F4 融合系数纯 DC 方向其实对，fused 被拉向市场稀释融合系数 a/b
F5 修正系数背锅开季×0.95/R3/温度等乘子把对的方向改错修正开关
② 信息层
输入缺失
补采集		F6 战意/轮换无欲无求、杯赛轮换、保级拼命——状态机没捕捉战意机消融去留

③ 随机层

只记账		F9 概率合理结果偏差p_final 与市场一致、xG 占优但输（单场方差，不是错）什么都不修，验随机占比
④ 执行层
入场/组票偏差
修纪律不修模型		F10 追买热入场CLV 为负，方向对也是负边际preference / 追热禁令
F11 票结构集中共享胆一挂双杀（T007/T008 本轮实锤）preference 共享胆规则

4. 总体架构与数据流

归因引擎作为新环节插入"回填赛果"链，位置在 corpus 之后、复盘报告之前：

5. 存储设计

独立落盘 data/04-summaries/attribution.json——因软标签和判别快照是"历史判断"不可重算，corpus 重刷不影响此文件。

{
  "schemaVersion": 1,
  "generatedAt": "2026-08-29",
  "records": {
    "2026-08-28|周五010|HAD": {
      "primary": "F3",
      "secondary": ["F5"],
      "evidence": {
        "pfinalPick": 0.42, "pinPick": 0.51,
        "agree": false, "weWrong": true,
        "chainDelta": 0.03,
        "lambdaGap": null, "scoreBias": "+1.5",
        "pinSource": "csv",            // csv（真收盘去水）| derived（反解·低置信）
        "oddsDrift": "+0.08"           // R5：score_odds 调价时间戳回放的赔率漂移
      },
      "source": "rule",                // rule | llm
      "confidence": "high",            // high | low（R4/R8/R10 标低置信）
      "confirmed": true,               // LLM 软标签待人工确认才进统计
      "note": null
    }
  },
  "factorStats": {
    "F3": {"nPrimary": 12, "nSecondary": 7, "avgProbGap": 0.07, "recoverableRate": 0.6}
  },
  "ablateCandidates": ["F2"],          // nPrimary≥20 进队
  "resolved": { "F11": "已修：共享胆规则进 preference" }
}

要点

  • key 与 corpus 对齐：date|code|play，回填重扫后同场覆盖（后写胜出，与 corpus 同规则）
  • evidence 全量化：每个因子判别时的数值依据存档，防"事后讲故事"，抽检有据可查
  • resolved 区：因子闭环后（消融定罪并修了 / 人工裁决不动）移入此区记账，避免重复进候选队列
  • confidence 字段：R4（F5 第一版降级）、R8（F9 垃圾桶自检）、R10（历史场无 λ）三处标 low，不进 factorStats 主统计

6. 规则归因判别决策树

attribute.py 对每道错题跑这棵树（自上而下，首个命中定主因，树上可再取至多 2 个强信号作次因）：

CRS 变体（R7）

corpus 里比分玩法 directionHit=null，标准入场条件与②市场分流对 CRS 场失效。变体明确化：

  • 入场条件：scoreHit=false && play=CRS
  • 市场分流：用"实际结果的三向"对比 pick 的三向（而非 directionHit）
  • 下钻：方向对+比分错时 F1/F2 判别优先于 F9；"带内比分没选中"（freq-band 排序问题）单独标 F1* 备注选法，不混入 λ 失准

7. 软标签流程与 skill 改动

触发条件（克制，三选一才请 LLM）

  1. 规则落 F9 但偏差剧烈（比分差 >2 球 / 半场全场倒挂）——"随机"可能是软因素没看见的遮羞布
  2. 证据弱场：树上两个因子信号都中等、主因勉强判出的
  3. 用户点名场次（复盘时"这场帮我归一下"）

LLM 判什么

只有 F6（战意/轮换）、F7（伤停）、F8 升主因这三件事。依据优先用可验证信源：体彩 insight 接口的伤停/近况数据（已有）、半场比分 half 字段（轮换嫌疑：下半场崩盘）、联赛格局画像（无欲无求/保级拼命）。

防污染纪律：软标签落盘带 source:"llm" + note（一句可验证依据）+ confirmed:false。未确认标签不计入 factorStats——复盘报告高亮列出待确认项，用户一句"确认"后才进统计。LLM 只能做两件事：将 F6/F7 升为次因、或改判主因；改判必须附信源。

skill 改动（SKILL.md 回填流程加一步）

现有：... → corpus → learn → dc重拟合 → 复盘报告
改为：... → corpus → attribute（规则归因）→ LLM补软标签（仅触发场）
      → 用户确认待确认项 → 复盘报告（含"偏差归因"节）→ commit

8. 统计口径与消融门

factorStats 口径（每因子滚动累计）

指标定义
nPrimary / nSecondary主/次因频次（按场去重：同场多玩法归因后统计只取主玩法 HAD 一条，防重复计数）
avgProbGap主因场中"错的那一向"我们 p_final 与市场/真实结果的平均概率差（=损失量，区分"高频小伤"与"低频致命"）
recoverableRate可修复率——F5场=重放翻转率、F3场=pin对的比例（回答"消掉该因子能救回几场"）
R3 树序偏差声明：factorStats 呈现时注明"主因分布按预设因果优先级产出，树序本身是待验证假设"；同时把次因信号纳入观察（F3 作次因的频率高=市场分歧其实更普遍），交叉印证树序是否人为压低了某些因子。
R2 信息优势审计触发：F3+F4 主因合计占比 >50% 时自动触发审计——模型 vs 市场 RPS 差 + CLV 分布全量。若结论是模型无信息优势，正确动作是把 a 降到 0（纯跟市场），结论如实呈报，由用户拍板。这不是 bug，是这套系统最锋利也最难接受的结论。

11. 与现有体系的关系

现有资产关系
corpus.json（255 条 records）数据源——attribute 读 records[] 的错题，归因结果写回 attribution.json（不污染 corpus）
ablate.py / calibrate.py反哺出口——候选因子进 ablate 消融，正增益走 calibrate 校准 a
trend.html（胜率趋势）表现层——attribution 是其归因层补充，二者并行不替代
preference.json（实票偏好）F10/F11 反哺对象——执行层因子改纪律不改模型
教训档案（SKILL references）叙事沉淀——R9 同题材双记，叙事给人看，账本给统计看
score_odds 日存档R5 判据源——oddsUpdatedAt 回放赔率漂移判 F10
