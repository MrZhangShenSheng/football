§0 由来与定位

2026-10-14 周三轮终审时，会话四路检索拿到 Sports Mole / Statz.ai / SportsGambler / SportyTrader / Forebet 等源对 007、014 等场的预测，其中 Statz.ai 顶格 1-1 与本地 LLM 31 格峰值逐格同框。但这些情报用完即弃：没有账本，不知某源历史命中率，也无法判断"多源同框"是真信号还是集体复读热门。本层即为此立。

定位铁线：纯观察层。不参与选腿、不排序候选、不加权共识分。若将来数据证明有决策价值，须另走组件准入制审计（v35 成例）方可入链。

§1 架构与数据流

新增一件工具 engine/scripts/web_preds.py，四子命令：

子命令职责
record <销售日> <entries.json>会话检索后按 schema 填条目文件 → 逐条七校验 → 分批冻结入 data/05-trends/{date}-webpreds.json。批次制：每批一 batchHash，追加不覆盖，已录条目永不可改
settle <销售日>从 data/02-results/ 取实际比分 → 判三格（方向/比分/市场对标）→ 写入结算区（与冻结区物理分离）
why <日|源|场次>三向回溯：按日出全卷、按源出历史、按场出全貌（仿 paper.py why 成例）
leaderboard [--json]汇总 data/04-summaries/web-source-ledger.json：每源 n / 方向率 / 比分率 / 对标值；n<30 标"积累中"不出口径

数据流：WebSearch → 会话填 entries → record 冻结 → 次日 settle → leaderboard 出榜 → 预测报告尾部"信源参考"区块展示。

回溯三道锁（大哥追问补强）

  1. 单一事实源：唯一真相只存 05-trends/{date}-webpreds.json 按日切片（与 02-results/05-trends 全仓惯例同构）；信誉榜只是视图，leaderboard 现算现写不另存二级真相——永无"榜与明细打架"
  2. why 一键三向：why 2026-10-14（按日）/ why Sports-Mole（按源）/ why 周三007（按场），纯读不改
  3. 防篡改对账：冻结预测区（batchHash 指纹覆盖）与结算区物理两分，"当时录了什么"与"后来结了什么"永远可分账；record/settle 后 git 留凭证提交
四路独立回溯：按日有切片 · 按源按场有 why · 按格有 hash · 按历史有 git

源名归一

engine/cache/web_sources.json slug 映射表，首见自动注册——防 "Sports Mole" / "sportsmole" / "SportsMole" 三写分裂同一源。

共识信号

record 时自动检测同场：≥2 源同比分→比分共识例；≥3 源同方向→方向共识例。各生成独立 consensus 条目附成员源册，settle 一并结算，满 30 例方判。

§2 判据预注册（冻结·改动即立项）

以下五条判据随本文档冻结于 2026-10-14。forward only：跑后不得挑口径、不得事后换阈值（铁律 14）。
  1. 方向率 = Σ directionHit ÷ n。n≥30 方出列，不足只报"积累中 n/30"
  2. 比分率 = Σ scoreHit ÷ n（同 n≥30 门槛）
  3. 市场对标差 = 该源偏离场（源方向 ≠ 市场热门方向）的方向率 −同场次集上市场热门自身的命中率。配对同集方成立：正＝源有真信息差，负＝复读机现形。偏离场 n_dev≥15 方报此列
  4. 市场热门口径 = 体彩 HAD 去水后最高概率方向。fd 断粮期无 Pinnacle 收盘可用，诚实标注，全场次统一口径不混源
  5. 共识例结算：比分共识例记比分率、方向共识例记方向率，各满 30 例方判

条目 schema（冻结区）

{"code": "周三007", "matchDay": "2026-10-15", "source": "Sports-Mole",
 "pick": "1:1", "outcome": "draw",          ← 工具派生，录者不填
 "publishedAt": "2026-10-12T18:00", "url": "https://…", "batch": 1}

record 七校验：① pick 形如 ^\d+:\d+$ ② url 必带且 http 开头 ③ publishedAt ≤ 开赛时刻（赛后源直接拒·防泄漏）④ code 须在当日在售清单 ⑤ source 过归一表（首见自动注册）⑥ 同批同源同场唯一（防重录）⑦ outcome 由 pick 派生后落卷。

结算区（settle 写）

{"actual": "1:2", "directionHit": true, "scoreHit": false,
 "vsMarket": {"favOutcome": "home", "isDeviation": true}}

§3 集成点 · 测试 · 范围

集成点（最小侵入）

  1. backfill 不挂：settle 先手动跑满三个轮次，验证对票无误后再议入自动链（一次一处）
  2. 首推展示：预测报告尾部"信源参考"区块，v1 手工贴榜
  3. LLM 卡 context 层不碰：web 情报与 LLM 语境层物理隔离，防 cardHash 链污染
  4. health_check 不加探测器（观察层无健康面）；webpreds 随轮 git 提交

测试清单（test_web_preds.py · 10 例）

schema 七条各一反例 ｜ slug 归一 ｜ 冻结幂等（同批拒·二批增）｜ outcome 派生 ｜ settle 三判据 + day±1 对票 ｜ n<30 出"积累中" ｜ 对标配对基线 ｜ 共识检测与例册 ｜ why 三向 ｜ leaderboard 出力。

范围（YAGNI 后）

做：web_preds.py（约 300 行）+ test_web_preds.py（10 例）+ web_sources.json 空表起步 + 本设计文档。
不做：爬虫、概率层（Brier/log-loss）、硬权重、health_check 探测器、backfill 自动挂链、时间衰减、源分级。

预期诚实声明：本层最可能的结局是"各源方向率≈市场热门命中率、对标差≈0"——即网络预测多为复读机，无信息差。这个负结果本身即有价值（省掉未来每轮的检索成本），与 tail-model FAIL 同等对待：按预注册红线处置，数据留作资产，不事后改判据抢救。
