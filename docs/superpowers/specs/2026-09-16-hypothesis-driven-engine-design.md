# 假设驱动出票引擎改造设计

日期:2026-09-16
拍板人:大哥
状态:待审

## 背景

2026-09-15 T033 全灭(30 元,CRS 2串1×3注),暴露的问题不在算得准不准,在决策逻辑本身。同轮彩票店老板误打编号形成的假设票(X033)中了 1356 倍,但那两场在现有引擎里**连候选资格都没有**——亚冠无联赛库被跳过,阿布艾因 4:0@175 超出赔率域上限。

大哥定调:以小博大,买彩票就是博小概率事件。预测应基于对各种影响因素的大胆假设,而非概率计算排序。命中率与 EV 不作出票门槛。

前一轮已把新流程写入 `data/06-tickets/preference.json`(`candidatePool` / `decisionFlow`),但**没有任何代码读它**——grep 全 `engine/` 目录仅 `boldplay.py:48` 一处行注释提及,引擎行为完全未变。本设计负责让引擎真按新流程跑。

## 目标

1. 撤销拦判断的闸门(赔率上限、带宽上限、无库场次跳过),保留赔率下限 4.0
2. 拦模型错误的闸门(`DIVERGENCE_LIMIT`)改为标注而非排除
3. 新增假设层,作为撤销闸门后唯一的拦截机制;DC 与模板降级为验证工具,不作推荐源
4. 反转锁死旧行为的测试

**不做**:不把 DC 接成默认推荐源(初稿曾列为目标,审核时判定与假设驱动冲突,已删)。

## 一、闸门改造

闸门分两类:**拦判断的撤销,拦模型错误的改成标注**。

### 1.1 撤销(拦的是判断,与以小博大冲突)

| 位置 | 现状 | 改成 |
|:---|:---|:---|
| `boldplay.py:43` | `ODDS_RANGE = (2.0, 40.0)` | `(4.0, float("inf"))` |
| `boldplay.py:31` | `SHAPES` 带宽 `(10,17)` / `(18,28)` | 上限撤销、下限降 4;桂林/梅州降级为参考标签 |
| `freq_band.py:25` | `BAND_DEFAULT = (10.0, 28.0)` | `(4.0, float("inf"))` |
| `boldplay.py:247` | `if not params: continue`(A-MIX 无库跳过) | 放行,标 `modelSupport: "none"` |
| `boldplay.py:631` | `if not (mid and had and params): continue`(彩票档无库跳过) | 同上 |

无库场次有**两处**跳过,必须同时改,否则两条路径行为不一致。

### 1.2 改成标注不排除(拦的是模型错误,不是拦胆量)

`DIVERGENCE_LIMIT = 0.05` 在代码中有六处引用,其中两处是过滤点:

- `boldplay.py:272 / 282 / 296` — `mix_candidates` 三池过滤
- `boldplay.py:663` — 彩票档 P0-3 分歧熔断

**全部改为:计算分歧值并写入卡面,但不再据此排除。**

设计过程曾拍板「彻底撤销」,后改口保留为标注,理由见 `boldplay.py:621-623` 注释:该熔断拦下的是 **DC 升班马污染参数**——弗洛西诺 `p_dc=94%` 曾以 EV+63% 假阳性混入 8 串。

这与 550 长尾是**两种不同的失败模式**:

| 成因 | 例子 | 该不该拦 |
|:---|:---|:---|
| 敢跟市场对赌 | 阿布艾因 4:0@175 | 不拦,这正是以小博大 |
| DC 参数本身算坏 | 弗洛西诺 `p_dc=94%`(升班马样本太少) | 拦不住也要标出来 |

5pp 分歧无法区分这两者,所以不能用它做排除;但也不能让它消失——否则大哥会按一个坏数字下注。改成标注:闸门不拦判断,但也不隐瞒模型可能有病。

### 赔率下限 4.0

下限 4.0 实际挡掉的只有方向层低赔腿(HAD 主胜 1.31 / 1.44 那类赔不动的腿)。以下全部保留:

- 马竞 2:0@6.5、米堡 2:1@7.25(T033 原腿)
- 巴列卡诺 2:1@7.75、阿布艾因 4:0@175(X033 两条腿)

### 撤销赔率上限的已知代价

代码注释记录:8-25 探针实测 `4:0@550 EV+845%` 曾被赔率域上限拦截,属尾部噪声假阳性。撤销上限后这类数字会重新出现。

阿布艾因 4:0@175 与该假阳性**在数学上无法区分**——都是低概率、超高赔、模型与市场大幅分歧。区别只在一个真的中了。因此上限不能用来防噪声:它挡掉假阳性的同时也挡掉了真机会。

防噪声职责转移给两处:分歧标注(§1.2)负责提示模型数可能有病,假设层(§二)负责人工否证。均不再由阈值自动排除。

### 无库场次放行

亚冠 / 解放者杯 / 联赛杯等无联赛库场次一律进候选池。比分层不给概率,只给赔率。选腿依据为可证伪的假设:主客强弱差、远征距离与时差、赛制压力(小组赛首轮 / 生死战)、伤停、轮换动机。

卡面须标 `modelSupport: "none"`,与有库场次区分。

## 二、假设层

卡内每场新增 `hypothesis` 字段,三段式:

```
assumption   一句可证伪的判断        例:"奥萨苏纳客场零封"
checks[]     回填验证逐条结果        H2H / 主客场分解 / 伤停 / 对手类型 / 赛制动机
verdict      survived | refuted     被数据打脸则 refuted
```

`verdict: refuted` 的腿不进候选。**这是撤销所有闸门后唯一保留的拦截**,拦的是没做功课,不是拦胆量。

### 决策流程三步与角色分工

| 步骤 | 做什么 | 谁做 |
|:---|:---|:---|
| 1 大胆假设 | 每场写一句可证伪判断,不看赔率、不看概率表 | **Claude 出,大哥审** |
| 2 小心验证 | 逐条查证,**只否决不排序** | Claude |
| 3 看赔率 | 存活假设中挑赔率最高者 | Claude 出方案,大哥定 |

**第 1 步分工细则:** Claude 读当轮全部场次的基础事实(近况、伤停、主客、赛制、H2H),为每场写一句可证伪判断,列成一页清单交大哥。大哥决定哪些认、哪些不认、哪些要改,也可直接追加自己的判断作为假设入单。

分工理由:Claude 能快速把 19 场的 H2H / 主客分解 / 伤停查完,大哥不必做这个;但**判断该不该信是大哥的事**——2026-09-15 大哥两次凭记忆纠正 Claude(「米堡 1:2 输了」、「4 月 3 日踢过」),方向均正确,而 Claude 的缓存是错的。

**本流程最易失效的环节是 Claude 出假设时偷懒。** 米堡 2:1 即为实例:Claude 写下「米堡主场场均进 3 球所以能打 2:1」,这句话本身就是未查证的假设,而 H2H 五分钟即可否掉。因此第 2 步的验证是专门用来否证 Claude 自己的假设的,不是走过场。

### DC 模型的位置:验证工具,不是推荐源

DC **不接默认路径**,保留为 `--method` 可选项与第 2 步的验证工具之一。

设计初稿曾把「默认路径接 DC」列为独立一节,现已删除。理由:

1. 大哥要的是假设驱动,DC 是概率驱动。把 DC 接成默认推荐源,等于把刚拆掉的概率排序换个名字装回去。
2. 本 spec「未解决」节已载明英冠 DC 不含 2026-04-03 米堡主场 1:2 负米尔沃尔、模型比 H2H 乐观。**已知不可靠的模型不该当默认。**

正确用法:大哥与 Claude 先出假设,再用 DC 查该假设站不站得住;而非让 DC 先排序、再从前几名里挑。

`freq_band` 模板同理降级。但模板的已知缺陷须记录在案,供第 2 步引用时警惕:

| 比分 | freq_band 模板 | DC 模型 | 893 场真实频率 |
|:---|---:|---:|---:|
| 马竞 2:0 | 6.2% | 12.61% | — |
| 米堡 2:0 | 2.5%(81 场小样本) | 9.87% | 5.8% |

米堡 2:0 那次误算(2.5% vs 真实 5.8%,低估 2.3 倍)是 T033 误剔除该腿的直接原因。模板用联赛通用频率、不含球队攻防参数;DC 用球队专属 `attack` / `defense` / `homeAdv` / `rho`,但受底层数据缺口影响。**两者都不可单独作为选腿依据。**

### checks 必含 H2H 数据完整度检查

2026-09-15 事故:据 260/552 的残缺缓存断言「H2H 只有 3 场」,漏掉 2026-04-03 米堡主场 1:2 负米尔沃尔——正是最该参考的一场(同对手、同主场、上赛季)。football-data.co.uk 的 E1 2526 仅至 2026-01-05,重拉不解决,须联网补。

因此 `checks[]` 中 H2H 项须同时记录:交手场次数、数据源赛季完整度、是否存在缺口区间。

### 反面案例(该被 refuted 的腿)

米堡 2:1。假设是「米堡主场场均进 3 球所以能打出 2:1」,而 H2H 四场米堡主场两次仅进 1 球、米尔沃尔为防守型球队,数据明确反对。买它不是大胆,是没做功课。

### 共用腿约束

共用腿禁止跨注复用充当分散。T033 三注共用米堡 2:1,表面 3 注实为 1 个失效点,米堡 2:2 一断三注同灭。

## 三、EV 与分歧值留在卡面

两者均保留在卡面,仅作标注,不作门槛。

设计过程中曾建议将 EV 从卡面主展示位撤掉(理由:+845% 假阳性与真机会外观相同,会误导),**该建议已撤回**。大哥指出:大乐透中奖概率两千万分之一、EV 为负,没人因此不买;小概率本身就是标的,不是缺陷。撤掉 EV 本质上仍是代替大哥做「这个太离谱不该买」的判断。

EV 与命中率降级为**事后复盘指标**,出票前不作劝退理由。

## 四、测试反转

`engine/tests/test_boldplay_mix.py:24` 的 `test_mix_odds_range_and_no_dc_skip` 锁死的正是本设计要撤的两个行为:

```python
# 该测试用 4:0@550 作探针,断言其被赔率域拦截
day["matches"][0]["crs"]["4:0"] = 550.0
assert all(l["odds"] <= boldplay.ODDS_RANGE[1] for l in legs)   # 上限锁点
assert all(l["matchNumStr"] == "001" for l in legs)             # 无库跳过锁点(002 无 DC)
```

断言反转为:

- 高赔长尾必须放行(175 级入选)
- 无库场次必须入选,且标 `modelSupport: "none"`——**两处跳过点各需一个测试**(`boldplay.py:247` A-MIX、`boldplay.py:631` 彩票档)
- 低于 4.0 的腿必须被挡
- 分歧超 5pp 的腿必须入选且带分歧标注(原为排除)

新增假设层测试:

- `verdict: refuted` 的腿不进候选
- `checks[]` 缺 H2H 完整度记录时报错
- 共用腿跨注复用时告警

同时排查 `test_boldplay.py` / `test_freq_band.py` 中引用 `DIVERGENCE_LIMIT` / `ODDS_RANGE` / `SHAPES` / `freq_legs` 的断言,逐条判断是锁死旧行为还是仍然有效。

## 未解决 / 需注意

**英冠 DC 底层数据缺口未修复。** `england-championship_dc.json` 拟合用的 341 场含 E1 2526 缺口(仅至 2026-01-05,缺 292 场),因此不含 2026-04-03 米堡主场 1:2 负米尔沃尔。DC 给米堡 λ=2.11,而 H2H 四场米堡主场两次仅进 1 球——模型与交手史方向不一致,DC 概率在此类场次偏乐观。假设层的 H2H 检查是当前唯一的补偿机制。

**撤销 DIVERGENCE_LIMIT 后卡面会变长。** 高赔长尾腿大量入选,需大哥与我逐条过假设清单。这是设计的预期代价,不是缺陷。
