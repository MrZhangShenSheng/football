# LLM 语境自主判断层（llm-context-autonomy）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended)
> or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** 淘汰 v2（31 格填表 + TTG 锚定 + 右尾选腿），改建「充分上下文进、自主判断出」的
LLM 预测层——把本地已算出的全部结论装进数据卡，松绑输出端硬格式，让判断本身成为产出与
受测对象，而不是让模型充当赔率模型的代餐。

**Architecture:** 厚上下文卡（市场五池去水 + V3W 实力链 + freq_band q + v4b 快照 + 情报
+ 首发 + 赛前新闻）→ 会话自主判断（结构化但非固定格式：走向/进球区间/关键格/反对项/置信，
每条带证据）→ 冻结落盘（判断即凭证）→ 出票按「判断关键格 × 市场价」偏离筛选 → 影子层
family L 新 epoch forward。

**Spec:** 待写 `docs/2026-10-16-llm-context-autonomy-design.html`（本 plan Task 0 产出）

## 诉求梳理（大哥 2026-10-16 口述 → 本节为待确认规格）

### 已明确的四条判决

1. **V2 必须淘汰**，不论 v3 成不成。不等对照、不留观。
   依据=判断与产出脱钩的实测证据（见下「淘汰依据」）。

2. **硬规矩给得太大**。现协议要求直接产 31 个概率数字，模型实际是用泊松摊格凑数
   （给主客期望 + 手调几格），产出本质是赔率模型代餐而非自主判断。

3. **上下文要给充分**：不只比赛情况，**还要包含"我们自己算出来的"**——即本地生产链
   已有的结论（实力链/去水概率/q 值/快照等），现卡里一概没有。

4. **按赔率筛比分是反直觉的，与赌博无异**。合理预测的结论应当是 `1:1`/`2:1` 这类，
   而非 `0:3`/`3:3`/`4:1`。

**机制定性**：`tilt` 是单参数全局缩放，总进球与形状在 31 格上耦合，调 TTG 必然动形状——
设计注释宣称的"TTG 锚市场、形状维度保留"在该实现下做不到。两步叠加（锚定削 54% + 右尾
筛掉剩余判断里偏离最大的格）后，该轨测量对象已与模型判断无关。

### 待大哥拍板的三个岔口

> 以下三项不同读法导向不同工程，**执行者勿自行假设**；Task 0 前须取得答复。

- **[Q1] 出票口径**：松绑后无 31 格分布，L 族选腿须换。候选 (a) 判断关键格 × 市场价，
  偏离大且价够肥才出；(b) 只出方向盘（HAD/HHAD），比分端仅作判断记录不出票；
  (c) 其他。
  —— 注：按已明确判决 4，候选池不应再设 @30 下限阈值。

- **[Q2] 判据处置**：`llm-predict-prereg.json` 冻结的主判据=31 格配对 log-loss，
  无 31 格分布即无法计算。候选 (a) 老 prereg 随 v2 一并退役，另立新 prereg（判据改为
  判断命中率/关键格校准/方向准确率等）；(b) 保留"由判断导出分布"接口以续用老判据
  （可比性保住，但会把填表重新引回来）。
  —— 我倾向 (a)；(b) 与判决 2 相悖。

- **[Q3] 输出端松到什么程度**：候选 (a) 完全自由文本判断，出票时人工读；
  (b) 结构化但不固定长度（走向/进球区间/关键格列表/反对项/置信，字段校验但不要求穷举
  31 格）；(c) 仍要分布但只要求"关键格 + 其余归一摊平"。
  —— 我倾向 (b)：可校验、可冻结、可对账，又不逼模型凭空产 31 个数。

### 不改的部分（守住的纪律）

- **forward only 红线**：模型见过历史赛果，样本只来自预注册后真实 forward；
  判断冻结落盘（时间戳 + cardHash 链）防事后改；预测必先于当日任何回填/赛果查询。
- **防赛后泄漏三道过滤**（语境层）：检索词限 preview/injury/team news；命中赛后特征词
  （FT/full-time/final score/终场/完场）整条丢弃；发布时间晚于卡 createdAt 不收。
- **幂等只读**：判断文件已存在直接返回，禁覆写（凭证纪律）；修正走 `-rN` 修正卷（R008）。
- **铁律 15 组件准入**：新轨入生产链前先过消融审计 + 跑前预注册；无审计不入链。
  本轨先在影子层 forward，不接出票主流程。
- **铁律 14②**：判据跑前冻结、跑后禁改口径。新 prereg 一旦 commit 即锁。
