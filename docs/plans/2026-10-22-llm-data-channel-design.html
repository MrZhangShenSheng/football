二、架构：按需获取制（节1 定稿）

核心原则

  • 不塞结论，开接口——与 v3.6 哲学同源：判断权在模型，数据通道机器供。卡层不预埋归因结论
  • 自动注入仅三样（当前比赛强相关+零争议+零泄漏）：赛制档案摘要/德比标记/两队剧本指纹（各近 10 场）
  • 频次表结论性内容不自动注入（t5 未过门）——模型想要自己查，查到也带 verdict 标注

三、七个查询命令（attribution_query.py）

命令数据源返回泄漏闸
formats <联赛>_formats.json该联赛赛制全档案无（静态）
derby <队A> <队B>_derbies.json是否德比+系数+样本 n无
freq <t1..t6>freq-tables.jsonn/diff/CI/verdict——仅 calibration_ready 给结论性措辞无
script <队> [N]hist 账本该队近 N 场剧本分布（画面指纹）仅已完场
h2h-dist <队A> <队B>hist 账本历史交手比分分布仅已完场
bill <日期> <码>forward 账本单场归因账单拒查未来/未完场日期
dim <E1..E5>设计文档字典维度定义说明无

调用方式：会话内模型发起 → Claude 代跑 CLI → 回贴 JSON。返回体自动带 n/样本期/verdict 标注——防小样本当规律、防 observational 当转正信号。

判断协议更新（SKILL.md v3.7 增量）

  1. keyJudgments 的 evidence 允许引用归因查询结果，引用须带命令名+关键数字（如 "script 查询：米兰近10场4次crush→支持0:2/0:3格"）
  2. verdict 纪律：observational 表只能作叙事线索，禁止作 direction/goalBand 移动的量化依据；calibration_ready 才可量化（当前零张——全部只能当叙事线索）
  3. shape.type 选择优先看剧本指纹——两队近 10 场剧本分布直接提示画面类型，归因数据进 v3.6 参数的最短路径

防泄漏边界

  • 七命令数据源全部赛前可观测或历史数据；bill/script/h2h-dist 查已完场场次，查询服务拒绝未来日期（查未踢场直接拒）
  • freq 表 verdict 随查询返回——模型无法拿 observational 当转正信号
  • 菜单位置固定在"缺口"节之前——数据获取不算判断，判断仍在市场正身之后做

五、数据源注册表（节3 定稿·扩展机制）

data/00-leagues/_data_registry.json——新数据源进预测链的唯一通路：

{
  "weather": {
    "cmd": "weather",                    ← 自动成为查询命令
    "desc": "球场天气/海拔(历史)",
    "path": "data/04-summaries/weather/",
    "leakRisk": "none",                  ← none|postmatch|conditional（查询闸依据）
    "verdictGate": false,                ← true=返回强制附 verdict+n/CI
    "autoInject": false,                 ← true=进 attributionPrior 自动注入
    "status": "active"                   ← retired 即下架（git 历史=准入凭证）
  }
}

三层接入位（由数据验证等级决定，不由代码决定）

层条件接入方式
L1 查询可及注册表登记即达view 菜单+查询命令（默认层·模型按需取）
L2 自动注入零争议确定性数据（如赛制档案）或 verdict=calibration_readyattributionPrior 层自动带出（注册表 autoInject=true）
L3 参数直改calibration_ready 且过组件准入审计（幸存链注册表）喂 v3.6 四闸系数/模板权重（当前零数据达此层）

未来新源（天气/裁判库/换帅事件/资金面…）同一条路：落位→登记→L1 可查→攒证据→升层。新源接入=加一条 JSON，不改卡层/查询代码；回滚=status: retired。
