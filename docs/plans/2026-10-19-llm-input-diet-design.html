二、卡面改造明细（llm_card）

2.1 市场正身化

  • 保留：五池原始价（可买性）、devig had/ttg（全量）、devig crs（全量保留——阅卷器 _baselines 依赖 power devig 做基线，砍了会静默退化为朴素去水；注意力靠段落定序解决，不靠删数据）
  • marketLambda 加 role: "market-derived"
  • v3wChain 删 crsTop5/lam（市场复印件），只留 src/water/ttgBoom/independentOfMarket/useNote
  • drift：ticks ≤ 1 时缩为 {"status": "单调无对照(ticks=1)"}

2.2 H2H 聚合

  • intel.h2h 增 seasonAgg：按 v3.3 赛季标聚合，形如 2627(1) 1平 · 2425(2) 弗2胜 · 2324(2) 萨2胜（胜者归属按主队视角换算）
  • 增 recent2（最近 2 场带赛季全文）；原 matches 数组保留（审计可回查，注意力走摘要）

2.3 standing 瘦身

  • intel.standing → {home: {ranking, 主分拆, 客分拆}, away: {...}}，其余原始键不进卡

2.4 缺口补齐三件

  • 对手排位 join：teamRecent 每行加 oppPos（对手当前 espn 排位；跨联赛/查不到 = null 不伪造）——近期形态从输赢序列升级为对手加权形态
  • 赛制性质标：卡头 competitionType——TAIL_LEAGUE_MAP 命中 = league（附 roundsPlayed），不命中 = 杯赛/未映射轮（轮换高风险·英锦标赛教训）
  • gen 前置 tick：llm_card gen 先 best-effort 跑一发 lineup_watch（晚场轮首发或已公布，卡能吃到就吃，失败不熔断）
  • 语境检索定为每轮固定步骤：context-todo → 会话检索 → write_context（流程约定，写进本文档与 plan）

2.5 判定协议硬规矩

  • llm_judge 输出契约说明加红字：「市场是基线不是答案——direction/goalBand/keyCells 的 evidence 必须引用市场以外材料（伤停/形态/排名/赛制/近期对手质量），只复述市场数字的判断按未做功课拒收」（会话纪律，不做机器强校验——正则拦不住换说法的复读）
  • 卡面段落定序（渲染序，非 JSON 键序）：市场正身 → 判断材料（intel/积分榜/近期/模型信号）→ 缺口置尾
  • prereg 增补一行 note（首次样本前的修订，记档）

三、测试与验收

  • 卡测试：市场正身（v3wChain 无 crsTop5、drift 缩行、lambda role）、H2H seasonAgg 聚合正确性（2627 1平/2425 弗2胜/2324 萨2胜）、standing 瘦身键集、oppPos join（含 null 不伪造）、competitionType 两态、gen 前置 tick（subprocess mock）
  • 渲染 007 卡人工复核注意力序
  • 全仓 pytest 回归

四、不做的事

  • 不删 devig.crs 全量（阅卷基线依赖）；不删 h2h.matches 全文（审计回查）；不动 prereg 判据本体（只增 note）；不机器强校验 evidence 反市场复读
