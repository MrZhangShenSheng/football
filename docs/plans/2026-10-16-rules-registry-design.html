经验规则化系统（rules-registry）设计

日期：2026-10-16 · 拍板：大哥（brainstorming 三问三答 + 设计五节逐节确认） · 动机：T048 之役三腿死于可预防教训（HAFU 过关／贴平腿／深水盘）——教训躺在 memory 里会被遗忘， 必须成为每次预测强制经过的核心逻辑；且未来所有经验都须有入编通道，规则本身也要能被证伪退役； 全程 context 可控。

§0 三大拍板（设计前提）

问拍板否决项与理由
治理形态C：自动候选＋人工转正闸——复盘/结算自动产候选，主公拍板才入编 A 人工 curated 会漏；B 全自动转正＝结论跑在证据前面（本仓回测自泄漏同病）
生效形态D：规则三段生命周期——候选→简报影子→硬闸转正，结算自动回测规则战绩，可退役 A 静态分流缺影子期——单例立规是臣 0.5 球标记案旧病；B 预算截断可能截掉最重要的规则；C 纯检索＝006 假伤停的失败模式本身
知识边界A：规则册＝唯一"预测生效"源——memory 降为纯叙事档案，SKILL 旧铁律行为禁令类迁入 多处并存必漂移（铁律4 融合公式漂移致复算 EV 差 19pp 实证）；编译自然语言源工程上脆

§2 规则 schema 与候选提取双通道

{"id": "R017", "addedAt": "2026-10-16", "source": "T048复盘",
 "stage": "candidate",          // candidate | shadow | gate | retired
 "form": "gate",                // gate=可代码化硬闸 | checklist=须人执行清单
 "trigger": {"play": "HAFU", "parlayMin": 3},   // 机器可判条件（gate 型必填）
 "text": "HAFU 腿禁入 3 串以上过关，只可单关或 2 串",
 "why": "013 方向全对(哥本哈根3:0)死于半场0:0——方向对也死",
 "evidence": [{"round": "2026-10-15", "legs": ["周四013"], "loss": 20}],
 "record": {"rounds": 0, "blocked": 0, "saved": 0, "harmed": 0},
 "rulings": ["2026-10-16 主公拍板①入影子"]}
gate 型必须带 trigger——无机器可判条件者永远升不了硬闸，只能停在简报层当日程提醒。

双通道：①复盘起草（主通道）——每轮回填复盘末尾强制二选一：起草候选或声明"本轮无新教训"，不许沉默跳过；text/why 臣写，证据字段从账本自动拉填。②模板扫描（辅通道）——结算钩子内置模式检测器（首版三模式：HAFU 过关腿死亡／贴平腿入票死亡／深水池腿死亡），命中给已有候选证据计数＋1；不能凭空立新候选——防机器归纳伪规则。

§3 生命周期判据（冻结数字）

转换判据（跑前冻结，改数字须拍板留痕）
候选 → 影子（拍板①）证据 ≥1 实战损失事件；主公拍板即可，无最低轮数
影子 → 硬闸（拍板②）record 满 5 轮 且 saved ≥1 且 harmed = 0；不满足继续影子
硬闸 → 降级/退役harmed ≥2 自动降回影子层标红待审；连续 20 轮零触发 标灰（场景消失，主公定夺）
候选淘汰30 天无新证据且未获拍板① → 标 stale（不删）
  • 判据只管 gate 型；checklist 型永停简报层，靠"连续 20 轮未执行留痕"触发同款复审
  • 单例可入影子、不可直入硬闸——5 轮影子是单例过拟合的最低保险
  • 退役不是删除：retired 全量留档，可检索性不丢（与"已证伪因素线清单"同构）

初版量预估：候选池 15-20 条（本轮 8 条＋历史迁移），影子层首批 8-10 条，硬闸 0 条——前 5 轮全靠简报层与执行留痕，即影子期本义。

§4 旧经验迁移方案

判别原则：只迁"行为禁令"，不迁"流程描述"。——它管的是臣不许/必须做什么（禁令），还是描述系统怎么运转（结构）？前者入册，后者原地不动。
旧载体去向
SKILL.md 十四铁律铁律 8（融合链四步）、5（模型≠必中）等流程/认知描述——留 SKILL；铁律 13 内核（EV 不选腿）、12（假设先行）、9（同场限一玩法）等行为禁令——入册
memory 教训条目行为部分（如 h2h-data-gap"判断前必查赛季完整度"）拆出入册；叙事留原地＋指针指向规则 id
CLAUDE.md项目第一约束（右尾）留 CLAUDE.md；其"操作推论"节（避热区/冷肥/不冷不肥）直接作用于选腿——拆出入册

段位判定：有实战损失证据者直接入影子（如铁律 9 的 011 混串案）；纯推理/证据久远者入候选。执行为一次性迁移任务，产出迁移审计表（旧条目→规则 id/留原地理由/段位），主公过目后旧条目加指针。分两批：首批只迁选腿/出票/核查三类（约 15-20 条，本轮 8 条并入）；第二批待首批跑稳再议。

§5 Context 控制细则

层常态成本
硬闸（代码）零
简报每轮 ≤15 条 ≈ 1500 token 封顶
候选池/退役档案零（转正评审按需读）
memory（降级后）索引常载不变，条目不再承担预测义务

编译时点：rule_brief.py 在 llm_card gen 后、填 31 格前——卡面摘要（~4000 token）＋简报（≤1500）合计 ≤6000 token。简报落盘 engine/cache/rules/briefs/{date}.md（凭证），两节：影子层全量（id｜条文｜战绩一行）＋候选池 trigger 命中者（仅提示）。溢出策略：超 15 条按 record.saved 降序保留，截断者列 id 明示"未注入 N 条"。

执行回执（影子期关键留痕）：臣每轮预测完成后在简报末尾追加——每条触发规则一行：R017 触发：拦下 周四013 HAFU hh（拟入3串）。被拦腿必记 code＋pick，结算钩子据此查赛果算 saved（拦腿死了＝救）/harmed（拦腿活了＝误伤）。

§6 与既有制度的关系

  • 与组件准入制同构：规则的影子期≈组件影子期，拍板②≈幸存链 PASS——本仓最成熟制度直接复用
  • 与影子票互补：影子票验证票的战绩，规则册验证规则的战绩
  • 与prereg 纪律一致：§3 判据跑前冻结，改数字须拍板留痕

§7 实施范围（YAGNI 后）
