设计 · 比赛过程数据实证（四层 × 一条验证轨道）

2026-09-02 · brainstorming 定稿（大哥拍板：四层全进调研·全面实证·review 修正三处后归档）｜核心问题：比赛内过程数据（半场比分/xG/技术统计/进球时间线）对 比分与玩法预测有没有可验证的增益

一、实测地基（两个硬事实）

  • fd CSV 有 15 个过程列一直没拉：HTHG/HTAG/HTR + HS/AS/HST/AST + HC/AC + HY/AY/HR/AR——抽查英超/西乙/希腊超三级联赛 100% 非空（半场比分零成本可得）；当前 odds_fetch 的列选择只存了比分+xG+赔率
  • goal_engine 验证轨道现成：match_features / lambda_mult / disable 消融参数 + walk-forward——新特征挂既有轨道，不走冷门因子"发现器立项"老路

二、总体架构

数据层（odds_fetch 扩列重拉）
  fd 12 过程列 + 既有 HxG/AxG → 两季 × 17 联赛 + EC0/SC0/EL0
        │
特征层（四条假设线，按先验分配资源）
  ① 半场比分 → HAFU 球队级 half_share      【真实证】
  ② xG → λ 收缩（goal_engine 乘子轨道）    【延期项·功效不足】
  ③ 技术统计 → 射正修正                    【引用文献·不实证】
  ④ 进球时间线 → late-goal 倾向             【源探测·不开则挂起】
        │
验证层（goal_engine 一条轨道）
  walk-forward + disable 逐特征消融 → 增益矩阵（4特征×4出口×RPS/log-loss）
  + 市场对照列（三向 vs pinClose / 总进球 vs OU2.5——其余出口无市场价，如实标注）
  铁律：CI95 全正→进主链 / 跨0→观察 / 含负→删

三、数据层

  • 扩列：odds_fetch.py:81-89 return dict 加 12 键（hthg/htag/htr/hs/as/hst/ast/hc/ac/hy/ay/hr/ar）——纯增列，既有 16 键行为不变（T1 契约），空值走 g() None 容错
  • 重拉范围：2526+2627 × 17 联赛 + 三杯赛码（约 3 分钟）；与层3 的 2425 拉取合并为一次网络任务
  • half_share 改造点：现 {meta, global, leagues} 联赛级 β 收缩（priorGoals=200）→ 球队级两级收缩（球队→联赛→全局回退链，与 elo/xG 画像回退同构）
  • 质量约束：杯赛文件过程列非空率 <80% 的联赛只进报告不进实证；重拉后 pytest 全量

四、review 修正三处（2026-09-02 大哥确认采纳）

修正1 xG 线延期：2627 仅 20~40 场/联赛（2526 无 HxG 列），xG-λ 球队级均值=每队 3~4 场，方差大到 w 网格搜是噪声拟合；walk-forward 每段 15 场功效不足。→ 产出功效分析结论（需 n≥100），等 2627 积累或 Understat 开源再验，本轮不写代码。
修正2 技术统计线降级为文献引用：预期低还要实证=重蹈冷门因子四轮证伪覆辙；xG 已包含其大部分预测力。"全面实证"按范围全覆盖·资源按先验分配执行：①真实证 / ②功效分析 / ③引用 / ④探测。
修正3 市场对照约束如实写：TTG 8档/CRS 31项/HAFU 9键无市场价（fd 仅 OU 2.5）——增益矩阵加"vs pinClose 去水（三向）+ vs OU2.5（总进球）"两列可对照出口，其余出口标注"仅模型内对照+抽水底线（q×体彩赔率 EV）"。

五、实现风险（动工前先验证）

  • HAFU 特征形态待读码：9 键=半场三向×全场联合分布，非"半场进球占比"单一参数可撑——实现第一步=读 dc_predict hafu 生成链（halfParams 构造），特征形态以读码结果为准，本设计的"两级收缩"是初步构想
  • 传导链验证：v5.3 起比分选法走 freq-band、DC 退出比分选择——"DC λ 变准 ≠ 比分预测变准"；验证矩阵必须含 goal_engine 轨的 TTG/CRS 出口（λ 平移是传导路径），不能只验 dc_predict 侧
