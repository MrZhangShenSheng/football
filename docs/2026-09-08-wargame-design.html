§一 背景与军事推演逻辑映射

大哥提出：借鉴军事推演（wargaming）的逻辑推演足球赛事走向。经概念映射与可行性甄别，得出三条真增量线与两个陷阱区：

军事推演概念足球对应本仓现状与判定
两阶段/多阶段裁决（先推阶段一，按态势推阶段二）上半场 → 下半场；HAFU 玩法天然对应真增量①——hafu 现为"三向条件分解"派生，非真两阶段推演；fd 自带 HTHG/HTAG 半场真果列，数据地基成立
分支与续章（branch & sequel）半场比分态 → 走向分化真增量②——narrative 剧本层仅 argmax 单剧本（实测 1:1 占 18/25），剧本树信息量大一个量级
红蓝对抗 + 裁决出票前"红队"攻击自己方案真增量③——信息边际三定律有雏形，无结构化反证流程
预警指标体系（I&W）赔率异动/伤停/首发 → 分支重估intel-timeline 已有数据底子，本设计暂不展开（R3 反证先吃红利）
指挥官意图建模战意/轮换/留力陷阱——战意状态机 2026-08-29 已消融证伪（n=9 无正增益降级叙事标注），意图做概率乘子必重蹈覆辙
蒙特卡洛推演万次模拟比分陷阱——DC 矩阵已是解析解，纯模拟无增量；分钟级事件模拟另因本仓无事件流数据源不可行（列未来方向）

§二 总体架构：两条腿 + 一套语言

项目代号 wargame。两个新模块（half_engine.py 模型层 / redteam.py 流程层）+ 一个共用表示（剧本树 scenario_tree）。

剧本树 = 模型层与流程层的共用语言：half_engine 产出分支（半场三向第一层 → 各分支下全场走向 top 路径），红队反证挂分支（"反证 X 成立 → 走向偏移到分支 Y"）。两模块通过树结构解耦、互不依赖、互不阻塞。

数据现状角色

侦察3 定义：实测本地 odds_{league}_{season}.json 的 HTHG/HTAG 列完整性（2425 全季 + 2526 快照）。fd 原始 CSV 半场列为标准配置，风险低；若本地缺列，等 fd 恢复补拉（外部依赖与 score-engine 段A 同一条，合并后只扛一次）。

侦察3 结论（2026-09-08 实测回填）：本地无逐场半场真果（三条路径全断），但 k 参数基建已现成（half_params.py = k 拟合器，half_share.json = k 值域）；段A 逐场结算部分挂 fd 恢复，P0-w 其余全部可先行

实测口径：① 本地 53 个 odds_*.json 缓存全量扫描——零半场键（odds_fetch.normalize_row 白名单未收 HTHG/HTAG，样本键仅 fthg/ftag/pin_*/b365c_*/ou_*）；② 仓库全域零 CSV（band_calibration.fetch_rows HTTP 直拉+内存解析不落盘）；③ fd 连通性今晨实测 HTTP 503（09-06 起限流持续，489 B 应答）。

重大发现：engine/cache/half_share.json（2026-08-26 生成，half_params.py）就是本设计 k 参数的现成拟合器产物——s 即 k（半场进球占比 λ_half/λ_full）：global s=0.4446 / 联赛级 8+ 条（英超 0.4431 n=1520 · 意甲 0.4376 n=1520 · 德甲 0.4621 n=1223 …），n=10898 场，β收缩 200 球 + clamp[0.3,0.6] + 全局自检（S_SANITY 0.40~0.50）全套与本设计 §二 k 拟合规格逐条对齐——half_engine 直接读 half_share.json 作 k 初始值，不重写拟合；rho_half 同取（DC 矩阵半场版相关性参数现成）。
