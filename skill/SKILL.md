## Step 1：赛事与赔率采集（必须完成）★ v4.1 双锚制

**赛程采集优先用脚本**：`python sporttery_fetch.py`（直连 API，绕过 WebFetch 截断，拿全部在售场次）。WebFetch 有长度截断（实测只能拿 18 场，实际 52 场），**仅作脚本失效时的备选**。

**双锚原则**：体彩赔率（毛利>7%）只用于**可买性判断**（能不能买、算奖金）；**概率锚**用 Pinnacle 收盘价（毛利~2.5%）去水。若 Pinnacle 数据不可得，标注"锚偏差 ~5pp，置信度下调一档"。

| 锚 | 来源 | 用途 |
|:---|:---|:---|
| 体彩官方 API | `sporttery_fetch.py`（直连，完整赛程+赔率） | 赛程编号、可买玩法、实际赔率、奖金计算、CLV 记录 |
| Pinnacle 收盘价 | oddsportal 存档 / Pinnacle 公开数据 / 搜索"match pinnacle closing odds" | 去水得市场真实概率，作为概率基准 |

必采字段：编号、联赛、主客队、开赛时间、**胜平负赔率 + 让球盘赔率**（逐一核验）+ Pinnacle 收盘三向赔率

检查项：

- [ ] 覆盖**所有比赛日**（不能只取第一天）
- [ ] 编号 × 联赛 × 主客队三重交叉验证
- [ ] 按联赛分组输出场次统计
- [ ] **场次完整性**：脚本拉取后核对编号连续性，如周五→周六→周日有断裂则补查（体彩偶有停售场次，编号跳号属正常）
- [ ] **双锚齐全**：至少 70% 场次拿到 Pinnacle 收盘价；未拿到的标注"锚缺失"并降级处理

输出：`| # | 编号 | 联赛 | 主队[排名] | 客队[排名] | 开赛日期时间 | 体彩赔率 | Pinnacle收盘 |`

> 每场比赛标注全局序号 #1~#N，方便后续所有环节交叉引用。报告输出必须带**日期 + 编号**（2026-08-21 实测教训：无日期/编号无法回填赛果）。

## Step 1.5：预筛选快排 ★ v4.0 新增

拿到赔率后、深度搜索前，先做一轮 30 秒快速分级：

| 赔率特征 | 分级 | 搜索策略 |
|:---|:---|:---|
| 单方概率 >60% 或 <15% | **高确定性** | 优先搜索，大概率 A/B 级 |
| 三项概率在 35%~50% 区间（极差 <10pp） | **胶着区** | 最后搜索；搜索后若仍胶着则标 C 级并标记"建议避开" |
| 胜平负未开售（仅让球盘） | **特殊场** | 标记为"仅让球/比分可用"，走让球盘反推流程（见 Step 4 修正系数 6） |
| 小联赛（瑞超/挪超/芬超/荷乙） | **高风险** | 仅搜索排名+交锋两项，快速判定能否达到 B 级；达不到直接标 D |

**搜索优先级排序**：高确定性场次 → 入串热门场次（三星以上潜力）→ 胶着区 → 高风险小联赛

## Step 2：双锚隐含概率（去水归一化）★ v4.1

```
p_i = (1/o_i) / Σ(1/o)      ← 对 Pinnacle 收盘价计算（概率基准）
```

- **概率基准** = Pinnacle 收盘价去水（毛利~2.5%，偏差最小）
- **体彩赔率** = 另行去水，仅用于计算实际价值（体彩赔率 vs 概率的正值判断）
- 胜平负盘与让球盘**分别计算**
- **盘口矛盾校验**：让球盘与不让球盘隐含概率矛盾时，以终端实盘为准并在报告中标注
- 体彩赔率与 Pinnacle 隐含概率差异 >7pp 的场次：体彩该选项无购买价值（负期望显著放大），报告标注

## Step 2.5：数据就绪检查 + 冷启动初始化 ★ v4.3 新增

预测前对每场检查三类数据，缺的先初始化再分析（RAG 冷启动闭环：初始化落盘，下轮同联赛/球队直接命中）：

1. **联赛画像** `data/00-leagues/{league}.json`：missing/stale → fd 覆盖联赛跑 `engine/scripts/run.py update`；不覆盖（日职/沙特/北欧/南美）WebFetch ESPN 积分榜结构化写入（standingsSource=espn-manual）
2. **球队画像** `data/01-teams/{league}/{teamId}.json`：lastUpdated >7 天或缺失 → 联赛分组搜索提取近5场/排名/伤停/主客战绩，按规范 JSON 写入（含 source）
3. **别名覆盖** `data/01-teams/_aliases.json`：中文名查不到 → 先补别名（规范 ID+zh+league）再走 ②

**执行方式**：调 `python data_check.py matches.json`（对阵清单 JSON）→ 拿到缺口报告（missingLeagues / missingAlias / notReadyTeams）→ 按清单初始化 → 复检。

**初始化优先级**：入串场次（三星+）球队 > 联赛积分榜 > 其余球队。联赛级初始化一次覆盖全联赛球队基础数据，比逐队省。

## Step 3：深度数据采集与分级

### 检索顺序 ★ v4.1：本地知识库优先 · v4.2 加联赛画像

```
1. 读 data/00-leagues/{league}.json → 联赛画像（积分榜/统计/争冠保级格局）
   ├─ fd 推导版由 league_profile.py 生成（engine/scripts/run.py update 自动）
   └─ 预测时 WebFetch ESPN 实时积分榜覆盖 standings（改 freshness.standingsSource=espn；轮次不一致标 stale）
2. 读 data/01-teams/_index.json → 哪些球队有本地画像？
3. 读 data/01-teams/{league}/{team}.json → Elo/xG/近况/伤停（新鲜则直接用）
4. 读 data/02-results/_h2h_index.json → 交锋（仅叙事参考，不进权重，见 H2H 降权）
5. 检查 engine/cache/{league}_dc.json 新鲜度（新增比赛 ≥5 场 → 调 dc_fit.py 重拟合）
6. 本地缺什么 → 只搜缺的（联赛分组批量）
```

### H2H 降权 ★ v4.1（学术依据：Groll 2018 特征重要性垫底）

- data/02-results/_h2h_index.json 保留存储，但检索层标注"仅叙事参考，不进权重"
- 预测推理时 H2H 不作为方向判断依据（阵容换血 + 信息已被实力评分覆盖）
- 例外：近 1 年内交锋 ≥2 次且战术风格延续的，可作定性参考（标注"弱参考"）

### 降级模式（数据源停摆常态预案）★ v4.9 新增

实测 2026-08 下旬 ESPN 赛果停摆 / Pinnacle 缺失 / 搜索配额耗尽**三重叠加是常态而非异常**，双锚体系实际常跑在体彩单锚。降级须量化处理，不做文字标注了事：

| 触发 | 处理 | 置信度代价 |
|:---|:---|:---|
| Pinnacle 收盘价缺失 | 概率锚退化为体彩去水（毛利 ~13%） | 修正后概率整体 ×0.97，星级上限 ⭐⭐⭐，报告标"单锚模式" |
| ESPN 积分榜停摆 | cn_fetch.py（titan007）兜底，全 0 榜跳过防污染 | 数据等级按实际覆盖重判（insight 即时排名可替代） |
| 搜索配额耗尽 | `insight <matchId>` 单场情报全量替代（伤停/近10场/排名/H2H 免配额） | insight 覆盖场可判 A 级 |
| 赛果回填 | 体彩编号对票主链路 + ESPN 兜底（backfill 双链路，v4.9 修复） | 无降级 |

### 搜索降级链 ★ v4.0 标准化

```
Transfermarkt 完整数据
  → 失败？降级到 espn_fetch.py 直连（积分榜 standings / 赛果 results）
    → 失败？降级到 cn_fetch.py（titan007 国内源）
      → 失败？降级到 flashscore 简要
        → 失败？Google 搜索单条验证
          → 失败？标 ❓ 放弃该项，不再重试
```

每个数据源**失败 1 次即降级**，不重试，节省 token。

### 联赛分组批量搜索策略 ★ v4.0 新增

把场次按联赛分为 3~4 组，每组用一条搜索词批量查：

```
示例分组：
- 欧罗巴组（6场）："Europa League playoff 2026 August recent form results"
- 日职组（2场）："J联赛 2026 standings recent results"
- 沙特联组（3场）："Saudi Pro League 2026 standings round X"
- 其余混合组（法甲/法乙/荷乙/芬超/瑞超）：各一条
```

每组搜索同时获取排名、近期战绩、交锋记录。单组失败才降级到逐场搜索。

| # | 检查项 | 查不到的处理 |
|:--:|:---|:---|
| ① | 历史交锋（近 3~5 场） | 标 ❓，置信度上限 ⭐⭐ |
| ② | 主队近期战绩（近 5 场） | 标 ❓，置信度上限 ⭐⭐ |

## Step 3.5：DC 模型概率 + logit 融合 ★ v4.1 新增

> 学术依据：模型与市场正常分歧 <3pp，>5pp 多半是模型错；融合优于对比告警（log-odds blending 是文献中少数被验证有效的提升手段）。

### 流程

```
1. dc_predict.py {主队} {客队} {联赛}
   → 读 engine/cache/{league}_dc.json（ξ=0.005 默认拟合）
   → 输出 7x7 比分矩阵 + 三向概率 p_DC
2. 融合：p_final = σ(a·logit(p_DC) + b·logit(p_pinnacle))
   → a/b 存 engine/cache/fusion.json（回测校准，初始 a=0.4 / b=1.0）
3. 融合偏差注记：|p_final - p_pinnacle| > 3pp → 标注"模型与市场分歧"
4. DC 缓存不可用（联赛历史数据不足）→ 跳过融合，p_final = p_pinnacle，标注"纯市场锚"
```

### 融合参数维护

- 初始 a=0.4, b=1.0（模型贡献 30-50% 权重区间）
- backtest.py 积累 ≥100 场后重校 a/b（最小化 RPS）
- 无回测数据前不得手动调大 a（防止高估自家模型）

### 修正三向回传 ★ v5.2 新增
Step 4 修正系数打完得到最终三向后，若本轮涉及比分/总进球/半全场玩法，必须回传拿全玩法自洽概率：
```
python engine/scripts/dc_predict.py <联赛> "<主队>" "<客队>" --market h,d,a --adjust H,D,A
```
- target 必须=融合+因子修正后的最终三向（裸 DC 修正禁止直传；JSON 带 source:"fused+factor-adjusted"）
- 三向和 ≠1（±0.001）会被拒绝；任一项 <0.01 会被 clamp 并 warn
- 输出 adjusted 块含重标定版 top_scores/ttg/hafu（已池级温度化）

## Step 6.5：出票前临场终审（最终方案逻辑校验）★ 出票必经

> 依据：2026-08-18 轮首次执行，赛前 8 小时复核推翻 2 个比分选项（马竞 2-0→1-0、凯尔特人 2-0→2-1），并纠正 2 处背景数据错误。

**触发**：出票前对每个入串场次执行，距开赛 ≤12 小时信息价值最高（发布会/官方伤报/首发预测均在此窗口发布）。

### 五项复核清单（每场）

| # | 复核项 | 关注点 |
|:--:|:---|:---|
| ① | 伤停 / 停赛终版 | **先跑 `sporttery_fetch.py insight <matchId>`（结构化伤停名单，含出场/首发数）**；再补官方医疗公告、欧战/杯赛停赛（如红牌跨赛事停赛）、训练伤退 |
| ② | 转会窗末段变动 | 核心球员离队官宣、新援注册资格、压哨交易风波（要求离队=军心变量） |
| ③ | 赛前发布会口径 | 主帅对首发/伤病/新援的表态（当日发布会信息最新鲜） |
| ④ | 官方赔率复扫 | 与上轮采集对比：**零异动+当日新消息=信息边际**；**赔率异动=市场已知消息** |
| ⑤ | 上轮赛后变量 | 体能/轮换留力、连胜/连败势头、数据纠错（复核可推翻 Step 3 结论） |

### 信息边际三定律（最终方案"符合逻辑"的判定标准）

1. **真边际 → 修订**：当日新信息（发布会/官方伤报）+ 官方赔率未调整 = 市场未消化的信息边际，允许修订选项。范例：2026-08-18 马竞攻击线五重减员（格列兹曼已走+Sørloth 官宣伤+阿尔瓦雷斯发布会确认不首发）当日齐发，赔率未动 → 比分 2-0 @6.25 改 1-0 @7.25，概率与赔率双升
2. **信息对冲 → 跟随市场**：新信息同时利好两个方向（如主队防线软肋 vs 客队欧战客场烂）时无边际，比分选项按市场热度（隐含概率最高者）选，不主观倾斜
3. **无边际 → 禁止调换**：无新信息时，同玩法选项间调换（如 2-0↔2-1）期望完全相同（同为该池抽水常数，见 Step 6 抽水率表），禁止以"感觉"换选项
4. **临场 adjust_map 同步 ★ v5.2**：临场复扫若当轮使用了 adjust_map，赔率复扫后**必须重算修正三向并同步更新 adjust_map 再重跑 boldplay**（旧三向×新赔率=错配）

### 比分决策速查表

| 临场信号组合 | 比分偏向 |
|:---|:---|
| 攻击线减员 + 对手摆铁桶/残阵 | **1-0** |
| 自身防线具体软肋（如边后卫青训客串）+ 对手有火力 | **2-1** 弃 2-0 |
| 主场零封能力强 + 对手欧战/客场成色差 | **2-0** |
| 两回合制首回合 | 小比分与平局概率整体上调，净胜 2 球把握下降（慎用让球胜）；胜平负层面 → 修正系数 5 平局保护 |
| 比分选择须注明：市场热度口径 或 信息边际依据，二选一 |

### 比分基础概率锚 ★ v4.0 新增

比分选择以联赛场均进球数为统计锚：优先读 `data/00-leagues/{league}.json` 的 `leagueStats.topScores`（当季实测）；无画像时用历史均值兜底表（日职 2.4/英超 2.8/西甲 2.3/法甲 2.3/德甲 3.0/沙特 2.6/解放者杯 2.1/欧罗巴 2.5 及各联赛 TOP3 比分），详表外置 `skill/references/coefficients.md`。若信息边际指向的比分不在 TOP3 中，必须标注依据。

### 高赔池全量 EV 扫描 ★ v5.1 新增（铁律 8 的执行细则）

每轮有 DC 概率的场次，三个高赔池**全量**跑 EV 扫描（`EV = p_model × 体彩赔率 - 1`），合规项 = EV>0 且 |p_model−p市场|<5pp：

- **CRS 31 选项全扫**——dc_predict 的 TOP1 比分只是概率锚（Step 6 比分基础概率锚），**不是选项依据**：高概率低赔 p×odds 常 <1（8-25 桂林A 取 TOP1 全低赔 EV-6.9%，全量扫后换 0-1 EV+2.2% 转正）
- **TTG 8 档 + HAFU 9 组合全扫**——dc_predict 已输出（ttg=list / hafu=dict；体彩赔率键 ttg 用 s0..s7、hafu 用 hh..aa、crs 用 sXsY），漏扫 = 白丢正值项（8-25 补扫 7 场出 9 个正值项，收金泉 HAFU dd@4.75 EV+5.5%）
- **同向偏差警惕**：同一选项多场同向 DC>市场（如 TTG 0球 4/4 场）疑模型系统病（ρ 修正系统性抬高 0-0），拒收待回填验证（8-24 已败一例）
- **HAFU dd(平/平) 是平局倾向的正确变现**（优于 HAD 平局 EV），主场平局率等硬数据优先
- 摘要卡逐池声明：`CRS 31×N场→X项合规 / TTG 8×N场→X / HAFU 9×N场→X`，为 0 也要写

### 至少中一注 = 耦合计算 ★ v5.1 新增（禁独立近似）

多注**共享同一胆材腿**时，禁止独立近似 `1−Π(1−pᵢ)`——8-25 实测高估 11.5pp（93%→82%）：5 注绑皇马腿，皇马翻车则连灭。必须按耦合路径算：

1. 按共享腿分组，组内注同生共死
2. 全灭概率沿共享腿翻车路径展开（皇马灭概率 × 剩余独立档灭概率 + 皇马中但双胆灭路径…）
3. 至少中一注 = 1 − P(全灭)；历史字段 hitAtLeastOne（8-23 0.564 / 8-24 0.515 均为独立近似，复盘时注意口径）

### 修订纪律

- 只允许"信息增强"方向修订（新事实推翻旧判断），禁止追高赔率方向修订
- 每处修订必须输出：修订项、旧→新、依据（具体新信息+来源）、赔率影响
- 终审后复核官方赔率未再异动方可出票；异动则重新走定律 1/2 判定

### 实票登记（出票即记账）★ v4.10 新增

用户实际出票后说"**我买了/出票了**"→ 立即写入 `data/06-tickets/tickets.json` + git commit（**git 历史=出票凭证**）：

```json
     "chain": "R3×0.95",                        // 修正系数链
     "ev": -0.031,                              // EV（p_model×odds-1）
     "inPlan": "B",                             // 入串方案名 / null
     // ↓ 回填时补齐：
     "result": "0-4", "directionHit": true, "scoreHit": null,
     "clv": null, "clv_approx_dk": -6.1, "clv_note": "..."
    }
  ]
}
```

> corpus.py 归一规则：grade 字母→数字（A=4）、pick 玩法前缀拆出 `play` 字段、league 去轮次后缀、fused→p_final。回填只改 `result/directionHit/scoreHit/clv*` 字段，**不动预测时锁定的其他字段**。

### 五维命中率统计

积累 N 轮后按六维拆解（联赛/星级/数据等级/修正系数/玩法五池/避开决策），各维统计命中率或应用 vs 未应用对比，用于调整波动系数、星级阈值、分级松紧、系数去留与方案模板权重（trend_report.py 自动输出）。

### CLV 逐单计算 ★ v4.1 新增（盈利性黄金指标）

> 学术/职业共识：判断单质量看 CLV，不看输赢。打平收盘 ≈ 零期望；稳定打赢 1.5-2% ≈ 长期正期望代理。

```
CLV = (出票赔率 / Pinnacle收盘赔率 - 1) × 100%
例：体彩主胜 1.86 出票，Pinnacle 收盘 1.72 → CLV = +8.1%（优质单）
例：体彩 1.45 出票，Pinnacle 收盘 1.55 → CLV = -6.5%（买贵了）
```

- 每单预测记录必含 `clv_approx_dk` 字段（DK 近似口径，trend_report 同算法，Pinnacle 停摆期不断粮）；Pinnacle 收盘价可得时才加填 `clv` 精确口径——两字段并行、近似口径保底（v4.9 口径）
- 复盘主指标：**场均 CLV**（正 = 选单能力过关，负 = 选单系统性偏差）
- 命中率仅作展示指标；RPS / log loss / CLV 为评估三件套

### 轮复盘模板

> 复盘报告保存到 `data/04-summaries/YYYY-MM-DD-review.html`。必含字段：方向命中率（✅ N/M）、比分命中率、本轮最佳/最差决策、系数验证（各系数应用 N 场命中 X 场 vs 基线）、避开价值（二星避开 N 场验证 X 场正确）、沉淀建议（是否调整系数/规则）。

### "避开决策"追踪 ★ v4.0 新增

> 从实战看，"避开"判断准确率似乎比"推荐"更高。需要量化验证。

所有标 ★★ 并建议避开的场次，必须跟踪赛果：
- 如果避开准确率 > 80% → 纪律有效，维持
- 如果避开准确率 < 60% → 说明二星场次中有些值得入串，需放宽条件
- 60%~80% → 维持现状，持续观察
