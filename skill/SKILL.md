## 一、执行流程（13 步）

> **★ v5.11 流程入口改写（2026-09-18）**：13 步是**计算流程**，不是**决策流程**。决策入口 = Step -1 假设层，
> 13 步只在假设存活后启动、且只做验证与选注，**不得用于选腿**。2026-09-16 大哥拍板原话：
> 「基于各种影响因素大胆假设，而不是计算概率；有了大胆假设再回填小心验证。」

## Step -1：假设层（决策入口）★ v5.11 新增（2026-09-16 拍板 / 09-18 补写进 skill / 09-22 v5.12 推演层）

**这一步在打开任何概率表、赔率表、EV 扫描之前执行。顺序颠倒即返工。**

### 四步铁序 ★ v5.12（原三步，"大胆假设"拆为推演+压缩两道工序）

| 步 | 动作 | 禁止 |
|:--:|:---|:---|
| ① **比赛推演** | 每个候选场写 `matchPlay` 五槽位（见下）——回答"这场比赛会怎么踢"。材料：insight + 积分榜 + 轮换惯例 + 赛制知识，**不新增采集** | 不得跳过推演直接写假设——没有画面支撑的 assumption 是统计特征罗列，不是预测（09-21 判例：英锦标赛轮漏判"小组赛大轮换"这一全场最强变量） |
| ② **假设压缩** | 从推演提炼一句**可证伪**判断（assumption）。用户观察 > 推演画面/球队特性/动机 > 统计特征 | **统计特征堆砌不得充当 assumption 主体**（"近10场7平+垫底+H2H全平"）——那是概率的另一种写法，不是比赛理解 |
| ③ **回填验证** | checks（H2H、主客分解、伤停、对手类型、赛制动机、日程密度）**只做否决不做排序** | 不得用验证结果给腿"打分排名"；不得把反对证据包装成"信息差对赌" |
| ④ **最后看赔率** | 在存活假设里挑赔率最高的比分/玩法；决定串法与注数 | **不得打开赔率表、概率表、EV 榜**（①②③全程）——看了就不是假设，是事后合理化。赔率是**选注工具**，不是选腿依据 |

### matchPlay 五槽位规范 ★ v5.12

**"真的预测比赛"的最小骨架**——槽位是检查表不是论文，每条一两句话：

| 槽位 | 回答的问题 | 反面判例（09-21 缺失项） |
|:--|:--|:--|
| `rotation` 轮换 | 本场预计轮换幅度/首发变动（含轮换惯例依据：赛制/赛程密度） | 英锦标赛小组赛大轮换 8-10 人惯例——全场最强变量，零覆盖 |
| `tactics` 战术对位 | 谁摆大巴/谁压出来/中场争夺/教练风格对撞 | 克劳利客场必然铁桶——没写 |
| `goalSource` 进球来源 | 两队靠什么进球（定位球/反击/阵地/头球） | 米尔顿只有头球点、破不了铁桶——没写 |
| `script` 比赛画面 | 节奏/走向/最可能的比分画面 | "低强度低节奏 0:0/1:0/1:1"——没有 |
| `specialVars` 本场特有变量 | 动机/天气/赛制/突发（点球积分制等） | 点球积分制——当时唯一及格项 |

**成本控制**：推演只做 Step 1.5 快筛后的候选场（典型 6~10 场）**+ 平局轨候选场**（排除方向但推荐平局的场恰恰最需要胶着剧本画面）；排除场（D 级/无锚直接排除）不推演——排除走 Step 1.5 定性快筛，与推演无关。

**落盘 schema**（hypothesis.json 每个假设新增 matchPlay 块）：

```json
{
  "matchNumStr": "周二002",
  "matchPlay": {
    "rotation": "预计双方轮换 6-8 人（英锦标赛小组赛惯例，两队周末均有联赛）",
    "tactics": "克劳利客场摆 5-4-1 铁桶，米尔顿阵地战渗透弱",
    "goalSource": "米尔顿定位球/头球为主；克劳利反击威胁低",
    "script": "低强度低节奏，0:0 / 1:0 / 1:1 画面",
    "specialVars": "点球积分制激励守平（点球胜2分/负1分）"
  },
  "assumption": "轮换环境下米尔顿锋无力+克劳利摆铁桶，90分钟平局被 4.25 低估",
  "checks": [ "...不变..." ],
  "verdict": "survived"
}
```

> 设计边界（大哥"不过度设计"原则）：matchPlay 全部定性描述，**无评分、无调参、不进概率权重**——它治理的是"假设从哪来"，不改 verdict 闸门逻辑；validate 不强制 matchPlay（旧数据兼容），执行质量靠自查与复盘对照。

### 判定标准（`hypothesis.py` 实现，必须实际调用）

- `make_hypothesis(assumption, checks)` 建假设；`verdict ∈ ("survived","refuted","pending")`
- **腿默认 `pending`；pending/refuted 一律进 `blockedByHypothesis` 不出票**——这是闸门全撤后唯一拦截
- **无锚场（dc_used=false）同等适用 ★ 2026-09-22 转正补条款**：联赛频率模板 / n>0 / q 值不是本场证据，纯模板腿 = pending 不得入票（09-17 杯赛轮 6 条 dc=null 模板腿直接入票为反例；v5.11 转正后引擎腿已全默认 pending，闸门挡在出票前）
- **晚上架补录场 ★ 2026-09-22 转正补条款**：出票前复扫发现新增上架场次，须补足假设 + 验证才可入票；来不及做功课的标"补录·未过假设层"禁入（09-18 周四002 上海申花上架晚于预测生成、10:24 复扫仅增量补录为反例）
- `filter_buyable(legs)` → (可买腿, 被挡腿)；`sort_by_hypothesis` 用假设优先序（survived → pending → refuted），**不用赔率降序**
- `check_shared_legs(bets)` 查共用腿伪分散（多注共用一腿 = 表面 N 注实为 1 个失效点）

### 唯一保留的硬拦截

**假设被数据直接否定的腿不买。** 反面案例 = 米堡 2:1（H2H 四场米堡主场两次仅进 1 球 + 米尔沃尔防守型，数据明确反对"米堡主场场均 3 球所以能打 2:1"）。买它不是大胆，是没做功课——**这条拦懒惰，不拦胆量**。

### 已撤销的门槛（不得复活）

带外例外（赔率形状带下限）、**EV 阈值**、**命中率下限**、freq_band q 值排序。这些从未真正拦截（T033 五条警示全标 🟡 不拦截、票照出全灭），且与"以小博大"冲突。

**EV / 命中率 = 事后复盘指标**，出票前不作推荐卖点、也不作劝退理由。大哥原话：「30 元赔进去无所谓」——0.86% 和 30% 命中率对他无意义，能不能中取决于假设对不对。

## Step 1：赛事与赔率采集（必须完成）★ v4.1 双锚制

**赛程采集优先用脚本**：`python sporttery_fetch.py`（直连 API，绕过 WebFetch 截断，拿全部在售场次）。WebFetch 有长度截断（实测只能拿 18 场，实际 52 场），**仅作脚本失效时的备选**。

**双锚原则**：体彩赔率（毛利>7%）只用于**可买性判断**（能不能买、算奖金）；**概率锚**用 Pinnacle 收盘价（毛利~2.5%）去水。若 Pinnacle 数据不可得，标注"锚偏差 ~5pp，置信度下调一档"。

| 锚 | 来源 | 用途 |
|:---|:---|:---|
| 体彩官方 API | `sporttery_fetch.py`（直连，完整赛程+赔率） | 赛程编号、可买玩法、实际赔率、奖金计算、CLV 记录 |
| Pinnacle 收盘价 | oddsportal 存档 / Pinnacle 公开数据 / 搜索"match pinnacle closing odds" | 去水得市场真实概率，作为概率基准 |

必采字段：编号、联赛、主客队、开赛时间、**胜平负赔率 + 让球盘赔率**（逐一核验）+ Pinnacle 收盘三向赔率

检查项：

- [ ] 覆盖**所有比赛日**（不能只取第一天）
- [ ] 编号 × 联赛 × 主客队三重交叉验证
- [ ] 按联赛分组输出场次统计
- [ ] **场次完整性**：脚本拉取后核对编号连续性，如周五→周六→周日有断裂则补查（体彩偶有停售场次，编号跳号属正常）
- [ ] **双锚齐全**：至少 70% 场次拿到 Pinnacle 收盘价；未拿到的标注"锚缺失"并降级处理
- **刷新即快照 ★ v5.4**：任何路径刷新 `sporttery_matches.json` / 拉取 insight 自动落盘 `data/05-trends/` 时序（钩子内嵌，失败不阻断）；手动补拍 `python engine/scripts/run.py snapshot [--insight 编号,编号]`

输出：`| # | 场次编号(体彩) | 联赛 | 主队[排名] | 客队[排名] | 开赛日期时间 | 体彩赔率 | Pinnacle收盘 |`（# 为全局序号，场次编号列=体彩编号 `周X00N`，两列并存职责不同勿混）

> 每场比赛标注全局序号 #1~#N，方便后续所有环节交叉引用。报告输出必须带**日期 + 编号**（2026-08-21 实测教训：无日期/编号无法回填赛果）。

## Step 1.5：预筛选快排 ★ v4.0 新增

拿到赔率后、深度搜索前，先做一轮 30 秒快速分级：

| 赔率特征 | 分级 | 搜索策略 |
|:---|:---|:---|
| 单方概率 >60% 或 <15% | **高确定性** | 优先搜索，大概率 A/B 级 |
| 三项概率在 35%~50% 区间（极差 <10pp） | **胶着区** | 最后搜索；搜索后若仍胶着则标 C 级并标记"建议避开" |
| 胜平负未开售（仅让球盘） | **特殊场** | 标记为"仅让球/比分可用"，走让球盘反推流程（见 Step 4 修正系数 6） |
| 小联赛（瑞超/挪超/芬超/荷乙） | **高风险** | 仅搜索排名+交锋两项，快速判定能否达到 B 级；达不到直接标 D |

**搜索优先级排序**：高确定性场次 → 入串热门场次（三星以上潜力）→ 胶着区 → 高风险小联赛

## Step 2：双锚隐含概率（去水归一化）★ v4.1

```
p_i = (1/o_i) / Σ(1/o)      ← 对 Pinnacle 收盘价计算（概率基准）
```

- **概率基准** = Pinnacle 收盘价去水（毛利~2.5%，偏差最小）
- **体彩赔率** = 另行去水，仅用于计算实际价值（体彩赔率 vs 概率的正值判断）
- 胜平负盘与让球盘**分别计算**
- **盘口矛盾校验**：让球盘与不让球盘隐含概率矛盾时，以终端实盘为准并在报告中标注
- 体彩赔率与 Pinnacle 隐含概率差异 >7pp 的场次：体彩该选项无购买价值（负期望显著放大），报告标注

## Step 2.5：数据就绪检查 + 冷启动初始化 ★ v4.3 新增

### 降级模式（数据源停摆常态预案）★ v4.9 新增

实测 2026-08 下旬 ESPN 赛果停摆 / Pinnacle 缺失 / 搜索配额耗尽**三重叠加是常态而非异常**，双锚体系实际常跑在体彩单锚。降级须量化处理，不做文字标注了事：

## Step 3.5：DC 模型概率 + logit 融合 ★ v4.1 新增

> 学术依据：模型与市场正常分歧 <3pp，>5pp 多半是模型错；融合优于对比告警（log-odds blending 是文献中少数被验证有效的提升手段）。

### 流程

```
1. dc_predict.py {主队} {客队} {联赛}
   → 读 engine/cache/{league}_dc.json（ξ=0.005 默认拟合）
   → 输出 7x7 比分矩阵 + 三向概率 p_DC
2. 融合：p_final = σ(a·logit(p_DC) + b·logit(p_pinnacle))
   → a/b 存 engine/cache/fusion.json（回测校准，初始 a=0.4 / b=1.0）
3. 融合偏差注记：|p_final - p_pinnacle| > 3pp → 标注"模型与市场分歧"
4. DC 缓存不可用（联赛历史数据不足）→ 跳过融合，p_final = p_pinnacle，标注"纯市场锚"
```

### 融合参数维护

- 初始 a=0.4, b=1.0（模型贡献 30-50% 权重区间）
- backtest.py 积累 ≥100 场后重校 a/b（最小化 RPS）
- 无回测数据前不得手动调大 a（防止高估自家模型）

### 修正三向回传 ★ v5.2 新增
Step 4 修正系数打完得到最终三向后，若本轮涉及比分/总进球/半全场玩法，必须回传拿全玩法自洽概率：
```
python engine/scripts/dc_predict.py <联赛> "<主队>" "<客队>" --market h,d,a --adjust H,D,A
```
- target 必须=融合+因子修正后的最终三向（裸 DC 修正禁止直传；JSON 带 source:"fused+factor-adjusted"）
- 三向和 ≠1（±0.001）会被拒绝；任一项 <0.01 会被 clamp 并 warn
- 输出 adjusted 块含重标定版 top_scores/ttg/hafu（已池级温度化）

### 方案模板 ★ v4.6 风险偏好三档重构

> 设计哲学：负期望空间里"激进"的正确姿势不是加大金额，是**同样的钱买更尖的赔率分布**。预算纪律（10~30 元/期）不动，档位内部自选。

### 方案输出硬规范 ★ v4.6：每选项必须标 概率×赔率×EV

> 下表为旧 🚀/⚖️/🛡️ 三段式配套示例（用户明确要求兼容输出时用）；默认输出 = 阶梯出票卡 v5.5 逐腿一行格式（见下方专节），EV 随腿标注（如 `主胜@1.20 EV+1.2%`）。**本节"逐注标概率×赔率×EV"的硬规范对两套表格同等生效**。

最终方案（摘要卡 + 详情）**逐注**输出：

```
| 注 | 玩法 | 选项 | p_model | 体彩赔率 | EV | 中奖奖金 | 命中概率 |
| 注① | CRS | 曼城 2-0 | 14.2% | 8.50 | +20.7% | 17 元 | 14.2% |
| 注② | HAFU | 马竞 平/胜 | 8.5% | 13.0 | +10.5% | 26 元 | 8.5% |
| 注③ | HAD 3串 | 胜/胜/胜 | 34.0% | 4.20 | +8.1% | 8.4 元 | 34.0% |
方案行：总投入 / 理论全中奖金 / 至少中一注概率 / 期望返还
```

- `p_model` = DC ttg/hafu/比分矩阵 或 市场锚融合概率（标注来源；`dc_used=false` 场次标"市场锚"）
- `EV = p_model × 体彩赔率 - 1`
- **★ v5.11 修订：EV≤0 不再是入选门槛**（原"EV≤0 的选项不得出现在方案"已撤销，与 Step -1 假设驱动冲突）。
  EV **照算照标**（事后复盘与 CLV 校准需要），但**不作选腿依据、不作推荐卖点、不作劝退理由**。
  出票门槛只有一条：假设是否被数据否定（Step -1）。
  违反实例：2026-09-18 会话用"整票 EV+256%"当卖点推方案、用"EV-47.9%"劝退另一方案，两个方向都套错目标函数。
- 串关 `p_model` = 各关概率连乘（关间独立假设，够用）
- **至少中一注概率** = 1 - Π(1-p_i)（独立近似）——衡量"这轮空手而归的可能性"
- **键序标注铁规 ★ v4.9**（2026-08-23 实票事故沉淀）：半全场组合/三向赔率必须显式标 h/d/a 键序并写全称一次（如 `aa（客/客）`、`dh（半平/全主胜）`），主客方向不得裸写缩写——曾因 hh/aa 键位语义看反致用户按错误标注出票（勘误见 r3.json idx2）
- 报告附来源清单（概率来自哪个 DC 缓存/市场锚），供事后 trend.html 校准图回验

### 资金纪律（负期望硬约束 · v4.6 档位化修订）

胜平负三向赔率和 ≈ 1.13 → 单关期望返还率 ≈ 0.871，**串 N 关期望 = (1-池抽水)^N**（HAD/HHAD 0.871 / TTG/HAFU 0.796 / CRS 0.661）——通用表见上方"抽水率 → 期望返还"。

**v4.6 档位规则**：
- 总仓位上限不变：单期 ≤10~30 元（数学依据不变）
- **档内预算**：🚀搏奖档 ≤10 元 / ⚖️平衡档 ≤15 元 / 🛡️保本档 ≤20 元（档位可组合，总仓位不破）
- 长串（3+）只允许 HAD/HHAD 材料；TTG/HAFU/CRS 最多 2 串；比分永远单关
- "激进"的正确实现 = 同预算下选更尖赔率分布（搏奖档），**不是**加注加倍——期望损失只和投注额成正比，和赔率形状无关

**红线（不可谈判）**：
- 用户处于债务/生活压力状态时只建议 2 元 1 倍，并明确告知：负期望游戏 + 固定目标 + 反复下注 = 破产概率趋近 100%，真实出口是协商/法律/现金流通道（如银行债务重组热线 12378）
- 禁止以"提高收益"为由推荐加倍、加关数；用户主动要求放大收益时，如实呈现抽水表后只给 ≤10 元的搏奖档选项（赔率形状激进可以，金额激进不行）

### 信息边际三定律（最终方案"符合逻辑"的判定标准）

1. **真边际 → 修订**：当日新信息（发布会/官方伤报）+ 官方赔率未调整 = 市场未消化的信息边际，允许修订选项。范例：2026-08-18 马竞攻击线五重减员（格列兹曼已走+Sørloth 官宣伤+阿尔瓦雷斯发布会确认不首发）当日齐发，赔率未动 → 比分 2-0 @6.25 改 1-0 @7.25，概率与赔率双升
2. **信息对冲 → 跟随市场**：新信息同时利好两个方向（如主队防线软肋 vs 客队欧战客场烂）时无边际，比分选项按市场热度（隐含概率最高者）选，不主观倾斜
3. **无边际 → 禁止调换**：无新信息时，同玩法选项间调换（如 2-0↔2-1）期望完全相同（同为该池抽水常数，见 Step 6 抽水率表），禁止以"感觉"换选项
4. **临场 adjust_map 同步 ★ v5.2**：临场复扫若当轮使用了 adjust_map，赔率复扫后**必须重算修正三向并同步更新 adjust_map 再重跑 boldplay**（旧三向×新赔率=错配）

## Step 8：赛果自动回填 + 五维复盘 ★ v4.0 新增 · v4.5.1 接闭环学习

### 触发方式

- **一键闭环**：`python engine/scripts/run.py verify`（backfill 双链路回填 → corpus → attribute → trend → calibrate → ablate 全自动；体彩编号对票为主链路，ESPN 兜底，未开赛场自动跳过、完赛后重跑即回填）
- **手动触发**：用户说"回填赛果" / "复盘上一轮"

回填后跑 `python3 engine/scripts/boldplay.py settle` 逐 leg 判定（比分 4串 部分命中 legHits 是层4实测库数据点），结果写回出票 JSON 的 settle 字段。

### 闭环学习接线 ★ v4.7 全链路（回填 → 验证 → 提升自动化）

- `python engine/scripts/run.py verify` 一键闭环：**backfill.py**（体彩编号对票主链路+ESPN 兜底，v4.9 双链路；未开赛自动跳过）→ **settle_tickets**（v4.10 票务结算：pending 实票对赛果→按形状算派彩→重刷 tickets.html）→ **boldplay.py settle**（v5.0 阶梯卡推演结算：逐 leg 判定，legHits 入层4实测库）→ **corpus.py**（语料+就绪度：重校 n≥100 / 消融 n≥50 / 断言 n≥15）→ **attribute.py**（规则归因：错题判别 F5/F9/F10 → attribution.json + factorStats，消融候选 nPrimary≥20）→ **trend_report.py**（趋势 ①~⑥ + ⑦回归断言 A1 校准/A2 星级/A3 系数/A4 DC 价值，静默=健康）→ **calibrate.py**（n≥100 网格搜 a∈[0.05,0.6] 最小 RPS；护栏：改善<1% 不动 / a 封顶 0.6）→ **ablate.py**（chain 触发 vs 未触发命中率；负增益>10pp 出 diff 建议人审，不自动改 SKILL.md）
- `python engine/scripts/run.py learn`：非fd联赛当年增量采集 → dc_fit --source local → models/ 版本发布（holdout 门槛）→ temperature 重拟（语料/fd 增量后，CI 不过自动 T=1）
- **回填时核对出票轮 livescan 存在性 ★ v5.12**：凡实际出票轮（02-results 有出票记录/tickets.json 有票），data/05-trends/ 必有当日 livescan.json——缺失=临场终审未落盘（09-19 缺口判例），当场追查补录或记纪律事件，不得静默放过

**chain 字段格式约定 ★ v4.7**：新轮预测必须存**结构化数组**（如 `["R1","保级平局"]`，消融器按关键词分桶），自由文本仅进 note——否则 A3 断言与 ablate 永远无法自动化。系数关键词映射见 ablate.py COEFF_PATTERNS。

**方案层准确率要点**（trend ⑥）：串关全中才算赢；统计各方案全中/断关/最弱环节 + **串关惩罚量化**（实测全中率 vs 单场命中率连乘理论值的落差——落差持续为正 = 修正系数系统性乐观，入串筛选该收紧）。单场准确率看 ①②④（概率层），方案准确率看 ⑥（出票层），两层不能互替。

- **模型版本存档**：`engine/cache/models/{league}_dc_v{n}.json + .meta.json`，`latest.json` 路由；发布门槛=holdout 不劣于当前版 2%+
- **本地赛果联赛**：日职 550 / 沙特 404 / 瑞超 376 / 韩职 597 场已回填 2025+2026 两季，四联赛 DC 首版已发布（韩职走体彩 league-results 口径）
- **回填率是硬通货**：门槛未达（重校 n≥100 / 消融 n≥50）calibrate.py/ablate.py 自动跳过；每轮回填都把就绪度推近阈值

每轮预测输出时同步生成结构化记录（保存到 `data/02-results/YYYY-MM-DD.json`，**遵守铁律 7 防覆盖**）：

> corpus.py 归一规则：grade 字母→数字（A=4）、pick 玩法前缀拆出 `play` 字段、league 去轮次后缀、fused→p_final。回填只改 `result/directionHit/scoreHit/clv*` 字段 + 增补 `pinClose/pinSource`（backfill 自动·fd 收盘三向），**不动预测时锁定的其他字段**。v4.7 起新轮 matches[] 必带 `lambdaHome/lambdaAway/fusedPre/chainSteps`（λ 与修正前融合自 dc_predict 输出透传；老轮不回补，归因引擎自动降级近似）。

### 五维命中率统计

积累 N 轮后按六维拆解（联赛/星级/数据等级/修正系数/玩法五池/避开决策），各维统计命中率或应用 vs 未应用对比，用于调整波动系数、星级阈值、分级松紧、系数去留与方案模板权重（trend_report.py 自动输出）。

### CLV 逐单计算 ★ v4.1 新增（盈利性黄金指标）

> 学术/职业共识：判断单质量看 CLV，不看输赢。打平收盘 ≈ 零期望；稳定打赢 1.5-2% ≈ 长期正期望代理。

```
CLV = (出票赔率 / Pinnacle收盘赔率 - 1) × 100%
例：体彩主胜 1.86 出票，Pinnacle 收盘 1.72 → CLV = +8.1%（优质单）
例：体彩 1.45 出票，Pinnacle 收盘 1.55 → CLV = -6.5%（买贵了）
```

- 每单预测记录必含 `clv_approx_dk` 字段（DK 近似口径，trend_report 同算法，Pinnacle 停摆期不断粮）；Pinnacle 收盘价可得时才加填 `clv` 精确口径——两字段并行、近似口径保底（v4.9 口径）
- 复盘主指标：**场均 CLV**（正 = 选单能力过关，负 = 选单系统性偏差）
- 命中率仅作展示指标；RPS / log loss / CLV 为评估三件套

### 轮复盘模板

> 复盘报告保存到 `data/04-summaries/YYYY-MM-DD-review.html`。必含字段：方向命中率（✅ N/M）、比分命中率、本轮最佳/最差决策、系数验证（各系数应用 N 场命中 X 场 vs 基线）、避开价值（二星避开 N 场验证 X 场正确）、沉淀建议（是否调整系数/规则）。
