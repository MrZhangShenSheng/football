## Step 1：赛事与赔率采集（必须完成）★ v4.1 双锚制

**双锚原则**：体彩赔率（毛利>7%）只用于**可买性判断**（能不能买、算奖金）；**概率锚**用 Pinnacle 收盘价（毛利~2.5%）去水。若 Pinnacle 数据不可得，标注"锚偏差 ~5pp，置信度下调一档"。

| 锚 | 来源 | 用途 |
|:---|:---|:---|
| 体彩官方 API | `https://webapi.sporttery.cn/gateway/uniform/football/getMatchCalculatorV1.qry?channel=c` | 赛程编号、可买玩法、实际赔率、奖金计算、CLV 记录 |
| Pinnacle 收盘价 | oddsportal 存档 / Pinnacle 公开数据 / 搜索"match pinnacle closing odds" | 去水得市场真实概率，作为概率基准 |

必采字段：编号、联赛、主客队、开赛时间、**胜平负赔率 + 让球盘赔率**（逐一核验）+ Pinnacle 收盘三向赔率

检查项：

- [ ] 覆盖**所有比赛日**（不能只取第一天）
- [ ] 编号 × 联赛 × 主客队三重交叉验证
- [ ] 按联赛分组输出场次统计
- [ ] **API 截断检查**：返回结果被截断时，用第二轮请求补充剩余场次（检查编号连续性，如有断裂则再次请求）
- [ ] **双锚齐全**：至少 70% 场次拿到 Pinnacle 收盘价；未拿到的标注"锚缺失"并降级处理

输出：`| # | 编号 | 联赛 | 主队[排名] | 客队[排名] | 开赛时间 | 体彩赔率 | Pinnacle收盘 |`

> 每场比赛标注全局序号 #1~#N，方便后续所有环节交叉引用。

## Step 1.5：预筛选快排 ★ v4.0 新增

拿到赔率后、深度搜索前，先做一轮 30 秒快速分级：

| 赔率特征 | 分级 | 搜索策略 |
|:---|:---|:---|
| 单方概率 >60% 或 <15% | **高确定性** | 优先搜索，大概率 A/B 级 |
| 三项概率在 35%~50% 区间（极差 <10pp） | **胶着区** | 最后搜索；搜索后若仍胶着则标 C 级并标记"建议避开" |
| 胜平负未开售（仅让球盘） | **特殊场** | 标记为"仅让球/比分可用"，走让球盘反推流程（见 Step 4 修正系数 6） |
| 小联赛（瑞超/挪超/芬超/荷乙） | **高风险** | 仅搜索排名+交锋两项，快速判定能否达到 B 级；达不到直接标 D |

**搜索优先级排序**：高确定性场次 → 入串热门场次（三星以上潜力）→ 胶着区 → 高风险小联赛

## Step 2：双锚隐含概率（去水归一化）★ v4.1

```
p_i = (1/o_i) / Σ(1/o)      ← 对 Pinnacle 收盘价计算（概率基准）
```

- **概率基准** = Pinnacle 收盘价去水（毛利~2.5%，偏差最小）
- **体彩赔率** = 另行去水，仅用于计算实际价值（体彩赔率 vs 概率的正值判断）
- 胜平负盘与让球盘**分别计算**
- **盘口矛盾校验**：让球盘与不让球盘隐含概率矛盾时，以终端实盘为准并在报告中标注
- 体彩赔率与 Pinnacle 隐含概率差异 >7pp 的场次：体彩该选项无购买价值（负期望显著放大），报告标注

## Step 2.5：数据就绪检查 + 冷启动初始化 ★ v4.3 新增

预测前对每场检查两类数据，缺的先初始化再分析（RAG 冷启动闭环：初始化结果落盘，下轮同联赛/球队直接命中）：

```
① 联赛进程数据 data/00-leagues/{league}.json
   ├─ ready（fd 自动生成或新鲜） → 直接用
   └─ missing/stale → 初始化：
       ├─ fd 覆盖联赛 → run.py update（odds_fetch + league_profile 全自动）
       └─ fd 不覆盖（日职/沙特/北欧/南美）→ WebFetch ESPN 积分榜 → 结构化写入
           （standings + freshness.standingsSource=espn-manual）

② 球队画像 data/01-teams/{league}/{teamId}.json
   ├─ ready（lastUpdated ≤7 天）→ 直接用
   └─ missing/stale → 初始化：联赛分组搜索 → 提取近5场/排名/伤停/主客战绩
       → 按规范 JSON 写入（含 source 标注）

③ 别名覆盖 data/01-teams/_aliases.json
   └─ 查不到中文名 → 先补别名（规范 ID + zh + league）再走 ②
```

**执行方式**：调 `python data_check.py matches.json`（对阵清单 JSON）→ 拿到缺口报告（missingLeagues / missingAlias / notReadyTeams）→ 按清单初始化 → 复检。

**初始化优先级**：入串场次（三星+）球队 > 联赛积分榜 > 其余球队。联赛级初始化一次覆盖全联赛球队基础数据，比逐队省。

```

### 联赛分组批量搜索策略 ★ v4.0 新增

```

- 欧罗巴组（6场）："Europa League playoff 2026 August recent form results"

## Step 3.5：DC 模型概率 + logit 融合 ★ v4.1 新增

> 学术依据：模型与市场正常分歧 <3pp，>5pp 多半是模型错；融合优于对比告警（log-odds blending 是文献中少数被验证有效的提升手段）。

### 流程

```
1. dc_predict.py {主队} {客队} {联赛}
   → 读 engine/cache/{league}_dc.json（ξ=0.005 默认拟合）
   → 输出 7x7 比分矩阵 + 三向概率 p_DC
2. 融合：p_final = σ(a·logit(p_DC) + b·logit(p_pinnacle))
   → a/b 存 engine/fusion.json（回测校准，初始 a=0.4 / b=1.0）
3. 融合偏差注记：|p_final - p_pinnacle| > 3pp → 标注"模型与市场分歧"
4. DC 缓存不可用（联赛历史数据不足）→ 跳过融合，p_final = p_pinnacle，标注"纯市场锚"
```

### 融合参数维护

- 初始 a=0.4, b=1.0（模型贡献 30-50% 权重区间）
- backtest.py 积累 ≥100 场后重校 a/b（最小化 RPS）
- 无回测数据前不得手动调大 a（防止高估自家模型）

## Step 4：8 因子加权评分 + 修正系数

### 加权框架

| 因子 | 权重 | 数据缺失时处理 |
|:---|:--:|:---|
| 赔率隐含概率 | 40% | 必有（官方） |
| 联赛排名差 | 15% | 必有 |
| 近期状态（近 5 场） | 12% | 缺失 → 置信度下调 |
| 主场优势 | 10% | 必有 |
| 历史交锋 | 8% | 缺失 → 忽略 |
| 伤停 / 阵容 | 8% | 缺失 → 忽略 |
| 战意（保级/争冠/杯赛） | 5% | 按排名推断 |
| 赛季阶段 | 2% | 开季前 3 轮整体降权（分档，见修正系数 1） |

### 修正系数（对概率做乘法修正）

> ★ v4.1 消融纪律：以下系数均为 hand-crafted，须由 backtest.py 逐条 on/off 回测验证。**回测无正增益（RPS/CLV）的系数降级为"参考"或直接删除**。消融状态标注：✅已验证 / 🧪待验证 / ⚠️证据薄弱。

**1. 开季修正（分档） ★ v4.0 升级 · 🧪待消融验证**

> 原 v3.2 问题："前 3 轮"一刀切 ×0.85 粒度太粗。第 1 轮冷门率远高于第 3 轮。学术对应物：升班马/大转会强度平移（Rue & Salvesen 2000，~0.5 球级先验注入）——消融时对比两种实现。

| 轮次 | 强队胜概率 | 平局概率 | 冷门概率 | 整体评级 |
|:---|:--:|:--:|:--:|:---|
| **R1**（赛季第 1 轮） | ×0.80 | ×1.35 | ×1.60 | 降 1 档 |
| **R2**（赛季第 2 轮） | ×0.90 | ×1.20 | ×1.35 | 降半档 |
| **R3**（赛季第 3 轮） | ×0.95 | ×1.10 | ×1.15 | 降 1/4 档 |
| R4+ | ×1.0（不修正） | ×1.0 | ×1.0 | 正常 |

> "轮次"定义：该联赛当季实际已踢轮数（非自然日）。从联赛官方积分榜确认。

**6. 让球盘反推规则 ★ v4.0 新增**

当胜平负玩法未开售、仅有让球盘时：

```
让球反推主胜概率 ≈ 让球盘主胜概率 × (1 - |让球数| × 0.08)
```

> 原理：让球数越大，让球盘主胜概率越偏向强队，但反推为不让球时需要打折。×0.08 为经验衰减系数（基于让球盘与胜平负盘的历史偏差）。

- 反推结果必须标注"让球反推估算"
- 反推概率仅用于方向判断，不用于比分预测
- 入串时优先使用已开售的玩法（比分/半全场/总进球），胜平负方向仅作参考

**7. 修正系数叠加封顶 ★ v4.0 新增**

> 原问题：多个修正系数同时触发时，概率可能被过度压缩（如"开季R1 ×0.80"+"首回合 ×0.92" 叠加 = ×0.736，失真）。

| 规则 | 内容 |
|:---|:---|
| **叠加封顶** | 同方向修正（都是压低主胜概率）的系数连乘后，总修正幅度不低于原始值的 **0.65**（即最多压掉 35%） |
| **反向系数独立** | 平局概率上调与主胜概率下调分别计算，不互相影响封顶 |
| **标注叠加** | 报告中如有 ≥2 个系数同时触发，必须标注"多系数叠加，已触发封顶" |

## Step 6：玩法匹配与串关方案（合规层）

### 4 类游戏规则速查（体彩官方）

| 游戏 | 关数上限 | 单场选项数 | 特点 |
|:---|:--:|:--:|:---|
| 胜平负 / 让球胜平负 | 8 关 | 3 选 1 | 命中率最高，赔率最低 |
| 总进球（0-7+） | 6 关 | 8 选 1 | 中等难度 |
| 半全场胜平负 | 4 关 | 9 选 1 | 难度高，赔率高 |
| 比分（31 个选项） | 4 关 | 31 选 1 | 难度最高，赔率最高 |

### 串关规则（木桶检查）

- 足球只能串足球
- **同场次可混不同游戏类型**（如 001 比分 + 001 胜平负），**不可同游戏多选**
- **木桶原则**：总关数 = 所选游戏中关数上限最低者（含比分/半全场 → ≤ 4 关）
- 纪律收紧：最多 4 串；含半全场/比分等高波动玩法时收紧至 **3 串**
- 奖金 = 2 元 × 各关赔率连乘 × 投注倍数

### 玩法 × 数据等级匹配矩阵

```
              比分    半全场   总进球   胜平负
A 级(6项)     ✅推荐   ⚠️可选   ✅推荐   ✅推荐
B 级(3-5项)   ⚠️搭配   ❌不选   ⚠️可选   ✅推荐
C 级(1-2项)   ❌不选   ❌不选   ❌不选   ⚠️仅方向
D 级(0项)     ❌       ❌       ❌       ❌
```

### 选场纪律

- 只选 A/B 级数据场次入串（C 级仅方向单选，D 级排除）
- 开季前 3 轮场次最多 1 场入串
- 小联赛（瑞超/挪超/芬超）最多 1 场入串，且不用比分玩法
- 优先选有交锋数据验证的场次；用户反馈场次优先
- 保级战执行平局保护检查

### 方案模板

**模板 A · 进攻型（纯比分搏高赔）**：2~4 场 A/B 级，1~2 场 A 级做稳胆，追求高回报。

**模板 B · 平衡型 ⭐ 推荐（混合串关）**：

```
① 数据等级最高的 1 场        → 【比分】搏高赔（~6-12 倍）
② 数据等级次高的 1~2 场      → 【胜平负】做稳胆（~1.3-2.0 倍）
③ 开季/小联赛场次一律用胜平负（非比分）
```

**模板 C · 稳健型（胜平负 N 串 M 容错）**：整体数据等级偏低时，3~4 场全胜平负，3 串 4 / 4 串 5，任错 1 场仍可回本。

预算示例：10 元以小博大，5 倍投注。每方案必须输出：各关玩法类型标注、数据等级链、预估赔率、预估奖金、木桶检查结果。

### 资金纪律（负期望硬约束，2026-08-18 增）

竞彩三向赔率和 ≈ 1.13 → 单关期望返还率 ≈ 0.885，**串 N 关期望 = 0.885^N**：

| 串关数 | 期望返还率 | 期望亏损率 |
|:--:|:--:|:--:|
| 单关 | 88.5% | -11.5% |
| 3 串 | 69.3% | -30.7% |
| 4 串 | 61.3% | -38.7% |

- **负期望空间的"最佳方案"唯一定义：最小成本 × 最大杠杆**（如 2 元 1 倍高赔串），不存在能救急/盈利的方案变体
- 娱乐仓位上限：单期 ≤10~30 元；用户处于债务/生活压力状态时只建议 2 元 1 倍，并明确告知：负期望游戏 + 固定目标 + 反复下注 = 破产概率趋近 100%，真实出口是协商/法律/现金流通道（如银行债务重组热线 12378）
- 禁止以"提高收益"为由向用户推荐加倍、加关数；用户主动要求放大收益时，如实呈现上表后只给 ≤10 元选项

## Step 6.5：出票前临场终审（最终方案逻辑校验）★ 出票必经

> 依据：2026-08-18 轮首次执行，赛前 8 小时复核推翻 2 个比分选项（马竞 2-0→1-0、凯尔特人 2-0→2-1），并纠正 2 处背景数据错误。

**触发**：出票前对每个入串场次执行，距开赛 ≤12 小时信息价值最高（发布会/官方伤报/首发预测均在此窗口发布）。

### 五项复核清单（每场）

| # | 复核项 | 关注点 |
|:--:|:---|:---|
| ① | 伤停 / 停赛终版 | 官方医疗公告、欧战/杯赛停赛（如红牌跨赛事停赛）、训练伤退 |
| ② | 转会窗末段变动 | 核心球员离队官宣、新援注册资格、压哨交易风波（要求离队=军心变量） |
| ③ | 赛前发布会口径 | 主帅对首发/伤病/新援的表态（当日发布会信息最新鲜） |
| ④ | 官方赔率复扫 | 与上轮采集对比：**零异动+当日新消息=信息边际**；**赔率异动=市场已知消息** |
| ⑤ | 上轮赛后变量 | 体能/轮换留力、连胜/连败势头、数据纠错（复核可推翻 Step 3 结论） |

### 信息边际三定律（最终方案"符合逻辑"的判定标准）

1. **真边际 → 修订**：当日新信息（发布会/官方伤报）+ 官方赔率未调整 = 市场未消化的信息边际，允许修订选项。范例：2026-08-18 马竞攻击线五重减员（格列兹曼已走+Sørloth 官宣伤+阿尔瓦雷斯发布会确认不首发）当日齐发，赔率未动 → 比分 2-0 @6.25 改 1-0 @7.25，概率与赔率双升
2. **信息对冲 → 跟随市场**：新信息同时利好两个方向（如主队防线软肋 vs 客队欧战客场烂）时无边际，比分选项按市场热度（隐含概率最高者）选，不主观倾斜
3. **无边际 → 禁止调换**：无新信息时，同玩法选项间调换（如 2-0↔2-1）期望完全相同（同为 0.885 去水常数），禁止以"感觉"换选项

### 比分决策速查表

| 临场信号组合 | 比分偏向 |
|:---|:---|
| 攻击线减员 + 对手摆铁桶/残阵 | **1-0** |
| 自身防线具体软肋（如边后卫青训客串）+ 对手有火力 | **2-1** 弃 2-0 |
| 主场零封能力强 + 对手欧战/客场成色差 | **2-0** |
| 两回合制首回合 | 小比分与平局概率整体上调，净胜 2 球把握下降（慎用让球胜）；胜平负层面 → 修正系数 5 平局保护 |
| 比分选择须注明：市场热度口径 或 信息边际依据，二选一 |

### CLV 逐单计算 ★ v4.1 新增（盈利性黄金指标）

> 学术/职业共识：判断单质量看 CLV，不看输赢。打平收盘 ≈ 零期望；稳定打赢 1.5-2% ≈ 长期正期望代理。

```
CLV = (出票赔率 / Pinnacle收盘赔率 - 1) × 100%
例：体彩主胜 1.86 出票，Pinnacle 收盘 1.72 → CLV = +8.1%（优质单）
例：体彩 1.45 出票，Pinnacle 收盘 1.55 → CLV = -6.5%（买贵了）
```

- 每单预测记录必须含 `clv` 字段（赛果回填时从 02-results 存档的 Pinnacle 收盘价计算）
- 复盘主指标：**场均 CLV**（正 = 选单能力过关，负 = 选单系统性偏差）
- 命中率仅作展示指标；RPS / log loss / CLV 为评估三件套
