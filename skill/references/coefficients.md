## 7. 修正系数叠加封顶 ★ v4.0 新增

> 原问题：多个修正系数同时触发时，概率可能被过度压缩（如"开季R1 ×0.80"+"首回合 ×0.92" 叠加 = ×0.736，失真）。

| 规则 | 内容 |
|:---|:---|
| **叠加封顶** | 同方向修正（都是压低主胜概率）的系数连乘后，总修正幅度不低于原始值的 **0.65**（即最多压掉 35%） |
| **反向系数独立** | 平局概率上调与主胜概率下调分别计算，不互相影响封顶 |
| **标注叠加** | 报告中如有 ≥2 个系数同时触发，必须标注"多系数叠加，已触发封顶" |

## 9. 伤停差值修正 ★ v4.8 新增 · 🧪待消融验证（数据源：`sporttery_fetch.py insight <matchId>`，2026-08-23 接通）

主力判定（insight injuries 字段，按队独立计算）：`starts/apps ≥ 0.7 且 apps ≥ 2` 判**主力缺阵**；其余为轮换缺阵（不修正）。位置系数：门将特殊处理，其余位置等权。

**符号约定（操作化定义，v4.9）**：`d = 主队主力缺阵人数 − 客队主力缺阵人数`，**正值 = 主队伤更重**（主胜被压低）。执行顺序永远先主后客，报告写带符号数值（`d=+2`）——2026-08-23 r5/r6 同场 d=±3 符号翻转事故后立此规矩。

| 主力缺阵差 d（主-客） | 概率修正 |
|:---:|:---|
| d ≥ +2 | 主胜 ×0.93，客胜 ×1.04 |
| d = +1 | 主胜 ×0.97 |
| 0 | 不修正 |
| d = -1 | 客胜 ×0.97 |
| d ≤ -2 | 客胜 ×0.93，主胜 ×1.04 |
| 任一方**主力门将**缺阵 | 受损方胜概率额外 ×0.95（与上表叠加，受系数 7 封顶约束） |

执行要求：
- 数据就绪判定：insight 缓存存在且 fetchedAt 当日 → 直接算；insight 无伤停数据（空数组）→ 按联赛主流源的伤停覆盖度标"参考"；未拉到 → 忽略（原 8 因子表缺失路径）
- 预测记录 `chain` 字段写 `伤停差值 d=±n`（含门将时加 `门将缺阵`），供 ablate.py 消融追踪
- 系数依据：hand-crafted 对齐学术文献伤停影响量级（~0.2-0.4 球 → 胜率 3~7pp），**n≥50 触发场前不得调大幅度**
